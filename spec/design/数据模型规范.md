# 数据模型规范

> **适用范围**：本文描述 **PDManer 数据模型（`.pdma.json`）** 中的定义，包括类型设置、数据域、主题域、标准字段库。
>
> - **大小写约定**：模型侧的实体表编码与字段编码使用**大写字母 + 下划线**（如 `BIZ_ORDER`、`CREATE_TIME`）；导出为数据库 DDL 时统一转换为**小写字母 + 下划线**。物理库基于 **MySQL 8.x**，规范见[数据库设计规范](数据库设计规范.md)。
> - 数据字典的编码规则与分类体系见[数据字典规范](数据字典规范.md)。
> - PDManer 文件的 JSON 结构见[数据模型文件格式说明](数据模型文件格式说明.md)。

## 1. 类型设置中的定义

### 1.1 基本数据类型

#### 1.1.1 字符串类型

- **字串类型** (`FC9790A7-36B8-4A48-8F9A-BC1042BCFE64`): 用于主键、外键等唯一标识字段，通常对应数据库中的VARCHAR类型

#### 1.1.2 数值类型

- **布尔类型** (`2285A896-2A28-4866-BD56-96AA2C2DC6E4`): 用于二值（True/False）的数值字段，例如：是否删除，是否有效等，通常对应数据库中的TINYINT类型
- **整数类型** (`1D764C4A-6F9F-421E-B11A-6F3E23B51811`): 用于较小范围的数值字段，例如：状态码、排序号等，通常对应数据库中的INT类型
- **长整数类型** (`934A2B58-BB77-4C06-ACC0-6F91F0ABF262`): 用于存储较大范围的数值字段，例如：订单号、自增的主键ID、去除小数位后以整数表达的金额，通常对应数据库中的BIGINT类型
- **小数类型** (`1A0BDC09-0792-4174-9E8E-80BE8DF44B8E`): 用于存储金额、比例等需要小数精度的字段，通常对应数据库中的DECIMAL类型
- **货币类型** (`812F9B49-930A-446C-9E55-A0D304460D6C`): 用于统一以最小货币单位（分或厘）存储的长整数金额，通常对应数据库中的BIGINT类型

#### 1.1.3 时间类型

- **时间戳类型** (`408D6058-481B-4D18-B037-4A80080C7694`): 用于记录时间信息，如创建时间、更新时间等，通常对应数据库中的DATETIME类型，精度为毫秒
- **时间点类型** (`978CF0B9-3FE3-4437-86E6-787D745663F3`): 用于记录时间点信息，如创建时间点、更新时间点等，通常对应数据库中的DATETIME类型，精度为秒级
- **仅日期类型** (`89D69E81-EA34-42EE-9FA2-93B8BD27E098`): 用于记录精确到天的年、月、日时间信息，如出生日期、统计日期等，通常对应数据库中的DATE类型
- **仅时间类型** (`2B9928F5-37D7-4C2F-8765-B849F5DAEF34`): 用于记录精确到秒的时、分、秒时间信息，如数据归属统计时间点等，通常对应数据库中的TIME类型

#### 1.1.4 其他类型

- **大文本类型** (`B17BDED3-085F-40E1-9019-3B79CF2BF075`): 用于存储大文本信息，如备注等，通常对应数据库中的TEXT类型
- **二进制类型** (`D516E75B-90F5-4741-B9B3-A186A263F04C`): 用于存储二进制数据，如图片、文件等，通常对应数据库中的BLOB或VARBINARY类型

### 1.2 数据域类型

#### 1.2.1 主键标识域

- **主键标识（GUID字串）** (`16120F75-6AA7-4483-868D-F07F511BB081`): 用于存储主键的唯一标识字符串，一般是去除分隔符的 UUID 字符串，引用基础数据类型中的字串类型，长度为32
- **主键标识（UUID字串）** (`E72D2CFB-3597-497A-B42B-D0405D4CA9C0`): 用于存储主键的唯一标识字符串，一般是包含分隔符的 UUID 字符串，引用基础数据类型中的字串类型，长度为36
- **主键标识（数值）** (`58ECA35E-8D59-42E1-85FD-8787A7308380`): 用于存储主键的唯一标识数值，一般是长整数类型，引用基础数据类型中的长整数类型

#### 1.2.2 文本域

- **普通字串** (`54611CCC-CA4B-42E1-9F32-4944C85B85A6`): 用于存储普通文本信息，如编号、名称、简短描述等，引用基础数据类型中的字串类型, 长度为90
- **备注文本** (`9092C4E0-1A54-4859-ABBB-5B62DBC27573`): 用于存储备注文本信息，如记录的备注等，引用基础数据类型中的字串类型, 长度为255
- **大文本** (`3E948CEC-3070-472C-AF92-F3CA11EC9D15`): 用于存储大文本信息，如备注等，引用基础数据类型中的大文本类型

#### 1.2.3 数值域

- **是否类型** (`6F7C1C5C-D159-41E6-BF9D-54DEEFA79AFF`): 用于二值的数值字段，例如：是否删除，是否有效等，引用基础数据类型中的布尔类型
- **整数** (`6BC8F04B-6CFA-4995-98D3-318F5CDD774E`): 用于较小范围的数值字段，例如：状态码、排序号等，引用基础数据类型中的整数类型
- **长整数** (`93A6C863-4559-49A9-8DE6-F4AA7D5470BA`): 用于存储较大范围的数值字段，例如：订单号、自增的主键ID、去除小数位后以整数表达的金额，引用基础数据类型中的长整数类型
- **货币类型** (`C3B1681B-99F9-4818-9E80-DE1652A51D85`): 用于存储去除统一的小数位并统一单位为厘表达的金额等，引用基础数据类型中的货币类型

#### 1.2.4 数据字典值域

- **数据字典值（整型）** (`F94EE328-4C2F-406C-A6DC-316A9EC9BCAD`): 用于存储数据字典明细的整型类型的编码，引用基础数据类型中的整数类型
- **数据字典值（字串）** (`73FD2BAD-2358-4336-B96D-45DC897BD792`): 用于存储数据字典明细的字符串类型的编码，引用基础数据类型中的字串类型，长度为36

#### 1.2.5 时间域

- **时间戳** (`220E480E-F1E9-4963-928C-79400ED27B63`): 用于存储时间戳信息，如创建时间、更新时间等，引用基础数据类型中的时间戳类型，精度为毫秒
- **时间点** (`5937A20F-7B44-4619-9858-010438AC6AA3`): 用于存储时间点信息，如创建时间点、更新时间点等，引用基础数据类型中的时间点类型，精度为秒级
- **仅日期** (`36C51739-83C8-432C-8B55-B5B60F82A458`): 用于存储仅日期信息，如出生日期、统计日期等，引用基础数据类型中的仅日期类型
- **仅时间** (`8A5931BC-7EC9-4CA3-938A-2AC7F058C0FD`): 用于存储仅时间信息，如数据归属统计时间点等，引用基础数据类型中的仅时间类型

## 2. 模型定义

### 2.1 主题域（Domains）

主题域用于对数据进行分类管理，包括：

- **通用域** (`84D0E3DE-A4D4-416F-A2A9-6FE1B8CC383F`): 存储系统相关的信息，例如：字典定义、字典明细等数据
- **授权域** (`E1001899-3889-44D9-8EEA-A7B18405DAC5`): 存储授权相关的信息，例如：用户、权限、角色、岗位等数据
- **业务域** (`D1DF205E-A3AD-4587-969C-5F0B17DA16AC`): 存储业务相关的信息，例如：商品、订单、客户关系等

### 2.2 数据字典（Data Dictionaries）

数据字典用于定义数据的标准化取值范围，例如：

- 状态字典：定义各种状态的标准化值和含义
- 类型字典：定义分类的标准化值
- 性别字典：定义性别的标准化选项

### 2.3 数据表（Tables）

数据表遵循以下设计规范：

- 实体表编码（`defKey`）使用大写字母和下划线（模型侧约定），导出 DDL 时转换为小写
- 必须包含注释说明
- 遵循命名规则（不允许保留字、特殊字符等）
- 表前缀按主题域划分，如 `SYS_`（系统）、`BIZ_`（业务）、`CFG_`（配置）

### 2.4 表字段（Fields）

表字段的设计要求：

- 字段编码（`defKey`）使用大写字母和下划线（模型侧约定），导出 DDL 时转换为小写
- 必须有注释说明
- 需要指定基础数据类型
- 可设置长度、小数位数等属性
- 支持主键、非空、自增等约束
- 可关联数据字典和数据域

### 2.5 索引（Indexes）

索引命名规范：

- 主键索引以 `pk_` 开头
- 唯一索引以 `uk_` 开头
- 普通索引以 `idx_` 开头
- 索引名全小写，使用下划线分隔

## 4. 建表同时生成的缺省字段

在创建数据表时，系统会自动添加缺省字段：

- **缺省字段可以引用标准字段，引用后，缺省字段的属性将同步标准字段的属性**
- **缺省字段的ID属性值需要重新生成，不能直接使用标准字段的ID属性值**

## 5. 其他重要配置

### 5.1 命名规则

- 表名和字段名使用英文大写字母和下划线
- 不允许使用空格和保留字
- 长度限制为32个字符以内

### 5.2 数据完整性约束

- 主键约束：确保每条记录的唯一性
- 非空约束：确保关键字段不为空
- 外键约束：不创建物理外键约束，仅在模型中维护逻辑关联关系，由应用层保证引用完整性
- 数据字典约束：确保字段值的标准化

### 5.3 索引策略

- 主键自动创建主键索引
- 外键建议创建索引以提高查询性能
- 常用查询字段可创建单独索引
- 避免过多索引影响插入性能
