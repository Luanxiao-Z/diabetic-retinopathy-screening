# 数据库设计规范

> **适用范围**：本文描述的是**数据库物理对象**，基于 **MySQL 8.x**（InnoDB 引擎）。
> PDManer 数据模型（`.pdma.json`）中的实体表编码与字段编码使用**大写字母 + 下划线**
> （如 `BIZ_ORDER`、`CREATE_TIME`），由工具在导出 DDL 时统一转换为本文规定的小写形式。
> 两者是同一对象的两种表示形式，映射规则见[数据模型规范](数据模型规范.md)。

## 一、表定义规范

### 1.0 字符集与排序规则

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 字符集 | `utf8mb4` | 全库统一，支持四字节字符 |
| 默认排序规则 | `utf8mb4_0900_ai_ci` | 不区分大小写、不区分重音，适合普通文本检索 |
| 编码类字段排序规则 | `utf8mb4_0900_as_cs` | **区分大小写**，用于字典域编码、字典项编码、权限编码、业务编码 |
| 存储引擎 | `InnoDB` | 全部表统一，禁止使用 MyISAM |

**编码类字段必须显式声明区分大小写的排序规则**：

```sql
domain_code VARCHAR(50) COLLATE utf8mb4_0900_as_cs NOT NULL COMMENT '字典域编码'
```

> 依据：项目要求编码类数据区分大小写（见[项目规则](../project/项目规则.md)）。MySQL 8 默认排序规则 `utf8mb4_0900_ai_ci` 不区分大小写，因此编码类字段必须单独指定 `as_cs`，否则 `C_STATUS` 与 `c_status` 会被判定为同一值。

### 1.1 表命名规范

| 规则项   | 规范要求                  | 示例                                     |
| ----- | --------------------- | -------------------------------------- |
| 命名格式  | 小写字母，单词间用下划线分隔        | `sys_user`、`biz_order`                 |
| 前缀规范  | 按模块/业务域添加前缀           | `sys_`(系统模块)、`biz_`(业务模块)、`cfg_`(配置模块) |
| 禁止使用  | MySQL 保留字、中文、特殊字符     | 禁止：`order`、`table`、`key`、`desc`、`range` |
| 长度限制  | 不超过30个字符              | `biz_product_category`                 |
| 关联表命名 | 主表\_从表形式，或使用`_rel_`连接 | `sys_user_role_rel`、`biz_order_product` |

> 确需使用保留字时必须用反引号 `` ` `` 包裹，但原则上应改名规避。

### 1.2 表设计规范

| 规则项  | 规范要求                       | 说明                                           |
| ---- | -------------------------- | -------------------------------------------- |
| 主键设计 | 每张表必须有主键，推荐使用单列主键          | 主键字段命名为`id`                                  |
| 主键类型 | `CHAR(32)` UUID（优先）或 `BIGINT` 自增 | UUID 为 32 位无分隔符字符串；`BIGINT AUTO_INCREMENT` 仅在需要顺序主键时使用 |
| 注释要求 | 表和字段必须有注释                  | 使用 MySQL 内联 `COMMENT` 语法                     |
| 存储参数 | 统一 `ENGINE = InnoDB`、`CHARSET = utf8mb4` | 见下方示例                              |
| 索引设计 | 根据查询条件创建合适索引               | 外键字段、常用查询字段建立索引                              |

### 1.3 表创建模板

```sql
CREATE TABLE biz_order (
    id              CHAR(32)       NOT NULL DEFAULT (REPLACE(UUID(), '-', '')) COMMENT '主键ID',
    order_no        VARCHAR(32)    NOT NULL COMMENT '订单编号',
    customer_id     CHAR(32)       NOT NULL COMMENT '客户ID',
    order_status    VARCHAR(20)    COLLATE utf8mb4_0900_as_cs NOT NULL COMMENT '订单状态(字典:B_ORDER_STATUS)',
    total_amount    BIGINT         NOT NULL DEFAULT 0 COMMENT '订单总金额（单位：分）',
    remark          VARCHAR(500)   DEFAULT NULL COMMENT '备注',
    state           TINYINT        NOT NULL DEFAULT 1 COMMENT '记录状态(字典:C_STATUS)',
    state_time      DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '状态时间',
    create_by       CHAR(32)       DEFAULT NULL COMMENT '创建人ID',
    create_time     DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    modify_by       CHAR(32)       DEFAULT NULL COMMENT '修改人ID',
    modify_time     DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '修改时间',
    is_deleted      TINYINT        NOT NULL DEFAULT 0 COMMENT '删除标记(字典:C_DELETE_FLAG)',
    versions        INT            NOT NULL DEFAULT 0 COMMENT '版本号（乐观锁）',
    PRIMARY KEY (id),
    KEY idx_biz_order_no (order_no),
    KEY idx_biz_order_customer (customer_id)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COLLATE = utf8mb4_0900_ai_ci
  COMMENT = '业务订单表';
```

> 说明：
> - `is_deleted` 仅在表需要对外同步时添加，见[2.3 同步表字段](#23-同步表字段)；常规业务表可省略。
> - `versions` 仅在表需要乐观锁时添加，见[2.4 并发表字段](#24-并发表字段)。
> - `modify_time` 使用 MySQL 原生 `ON UPDATE CURRENT_TIMESTAMP` 自动维护，见[2.2.1](#221-modify_time-维护方案)。
> - 主键默认值 `REPLACE(UUID(), '-', '')` 需 MySQL 8.0.13+ 支持表达式默认值；低版本改为由应用层生成 32 位 UUID 并在插入时赋值。
> - 已建表补充表注释：`ALTER TABLE biz_order COMMENT = '业务订单表';`

## 二、字段定义规范

### 2.1 字段命名规范

| 规则项  | 规范要求                   | 示例                          |
| ---- | ---------------------- | --------------------------- |
| 命名格式 | 小写字母，单词间用下划线分隔         | `user_name`、`create_time`   |
| 布尔类型 | 使用`is_`前缀              | `is_enabled`、`is_deleted`   |
| 时间类型 | 使用`_time`或`_date`后缀    | `create_time`、`birth_date`  |
| 数量类型 | 使用`_count`或`_num`后缀    | `view_count`、`order_num`    |
| 金额类型 | 使用`_amount`或`_price`后缀 | `total_amount`、`unit_price` |
| 编码类型 | 使用`_no`或`_code`后缀      | `order_no`、`product_code`   |
| 名称类型 | 使用`_name`后缀            | `user_name`、`category_name` |
| 外键类型 | 使用关联表名`_id`后缀          | `user_id`、`dept_id`         |
| 业务状态类型 | 使用`status`或`_status`后缀，取值必须关联业务字典域 | `order_status`、`audit_status` |
| 通用记录状态类型 | 固定使用`state` | `state` |

> **重要区分**：`state` 是**通用记录状态**（有效/失效，字典域 `C_STATUS`），每张表的标准字段之一；`status` 是**业务状态**（如订单状态、审核状态），必须关联具体业务字典域。二者不可混用，一张业务表中可同时存在 `state`（记录级）与 `xxx_status`（业务级）。

### 2.2 标准字段定义

每张业务表应包含以下标准字段：

| 字段名           | 数据类型        | 必填 | 默认值                                | 说明                   |
| ------------- | ----------- | -- | ---------------------------------- | -------------------- |
| `id`          | CHAR(32)    | 是  | `REPLACE(UUID(), '-', '')`          | 主键ID，32位UUID（优先）      |
| `state`       | TINYINT     | 是  | 1                                  | 记录状态（字典:C_STATUS）    |
| `state_time`  | DATETIME    | 是  | CURRENT\_TIMESTAMP                 | 状态时间                 |
| `create_by`   | CHAR(32)    | 否  | NULL                               | 创建人ID                |
| `create_time` | DATETIME    | 是  | CURRENT\_TIMESTAMP                 | 创建时间                 |
| `modify_by`   | CHAR(32)    | 否  | NULL                               | 修改人ID                |
| `modify_time` | DATETIME    | 是  | CURRENT\_TIMESTAMP ON UPDATE CURRENT\_TIMESTAMP | 修改时间（自动维护） |

### 2.2.1 `modify_time` 维护方案

**MySQL 原生支持列级 `ON UPDATE CURRENT_TIMESTAMP`**，推荐直接使用数据库能力：

```sql
modify_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '修改时间'
```

注意事项：

1. 仅 `TIMESTAMP` 与 `DATETIME` 支持该语法；本规范统一使用 `DATETIME`（避免 `TIMESTAMP` 的 2038 年上限）。
2. 使用 `ON UPDATE` 时，若 UPDATE 语句显式赋值该字段，以显式值为准。
3. 若需兼容其他数据库或统一由应用层控制审计字段，改用 **MyBatis-Plus 自动填充**：

   ```java
   @TableField(fill = FieldFill.INSERT_UPDATE)
   private LocalDateTime modifyTime;
   ```

   ```java
   @Override
   public void updateFill(MetaObject metaObject) {
       this.strictUpdateFill(metaObject, "modifyTime", LocalDateTime.class, LocalDateTime.now());
   }
   ```

**各数据库自动更新时间支持情况**：

| 数据库 | 列级 `ON UPDATE` 语法 | UUID 生成方式 |
| --- | --- | --- |
| **MySQL 8** | ✅ 支持 `ON UPDATE CURRENT_TIMESTAMP`（5.6.5+ 起 DATETIME 亦支持） | `UUID()`（36 位带分隔符），需 `REPLACE(UUID(),'-','')` 得 32 位 |
| 达梦 DM | ❌ 不支持，需触发器或应用层维护 | `SYS_GUID()`（32 位十六进制） |
| Oracle | ❌ 不支持，需触发器 | `SYS_GUID()` |
| PostgreSQL | ❌ 不支持，需触发器 | `uuid_generate_v4()`，需先 `CREATE EXTENSION IF NOT EXISTS "uuid-ossp";` |

`CURRENT_TIMESTAMP` 作为默认值在 MySQL、达梦、PostgreSQL 中均支持。

### 2.3 同步表字段

当表需要对外同步时，需要包含以下字段：

| 字段名 | 数据类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `is_deleted` | TINYINT | 是 | 0 | 删除标记（字典:C_DELETE_FLAG），0=未删除，1=已删除 |

**仅靠modify_time字段无法实现删除记录的同步，故需要结合is_deleted字段进行区分**

### 2.4 并发表字段

当表需要并发表时，需要包含以下字段：

| 字段名 | 数据类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `versions` | INT | 是 | 0 | 版本号 |

**应用采用乐观锁机制，版本号字段用于记录记录的修改次数**

### 2.5 字段设计规范

| 规则项      | 规范要求               | 说明                                                                                                                                                             |
| -------- | ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| NULL约束   | 业务关键字段设置NOT NULL   | 避免数据不完整                                                                                                                                                        |
| 默认值      | 合理设置默认值            | 数值如业务无明确定义则默认0;字符串默认空串或NULL;时间点默认当前时间戳; |
| 树型结构父级字段 | 父级节点字段默认值根据主键类型确定  | 主键为CHAR时默认值为NULL，主键为BIGINT时默认值为0或-1                                                                                                                         |
| 字段注释     | 所有字段必须有注释          | 说明字段含义，字典字段标注字典编码                                                                                                                                              |
| 长度定义     | 根据业务需求合理定义         | 预留一定扩展空间                                                                                                                                                       |
| 编码字段排序规则 | 编码类字段使用 `utf8mb4_0900_as_cs` | 保证大小写敏感，见[1.0 字符集与排序规则](#10-字符集与排序规则) |
| 精度定义     | 金额类字段使用长整数，最小单位为1分 | BIGINT                                                                                                                                                         |
| 禁止使用     | MySQL 保留字作为字段名  | 如：`desc`、`key`、`range`、`order`、`rows`、`rank`                                                                                                                                     |

## 三、数据类型定义规范

### 3.1 MySQL 数据类型对照表

| 分类        | MySQL 类型      | 取值范围 / 说明                  | 使用场景      | 示例                       |
| --------- | ------------- | -------------------------- | --------- | ------------------------ |
| **布尔/枚举** | TINYINT       | 1 字节（常用 0/1）               | 二值、是否、开关   | `is_locked TINYINT`      |
| **整数类型**  | TINYINT       | 1 字节                       | 业务状态标记    | `order_status TINYINT`   |
| <br />    | SMALLINT      | 2 字节                       | 小范围数值     | `sort SMALLINT`          |
| <br />    | INT           | 4 字节                       | 常规整数      | `age INT`                |
| <br />    | BIGINT        | 8 字节                       | 主键ID、金额（分） | `amount BIGINT`          |
| **浮点类型**  | FLOAT         | 单精度，有精度损失                  | 科学计算（非金额） | `rate FLOAT`             |
| <br />    | DOUBLE        | 双精度，有精度损失                  | 高精度科学计算   | `precision DOUBLE`       |
| **定点类型**  | DECIMAL(p,s)  | 精确小数                       | 需精确保留小数的数值 | `ratio DECIMAL(10,4)`    |
| **字符类型**  | CHAR(n)       | 定长，n ≤ 255                 | 固定长度编码（UUID 主键） | `id CHAR(32)`      |
| <br />    | VARCHAR(n)    | 变长，按字符计数                   | 可变长度字符串   | `name VARCHAR(100)`      |
| <br />    | TINYTEXT      | ≤ 255 字节                   | 极短文本      | —                        |
| <br />    | TEXT          | ≤ 64 KB                    | 大文本内容     | `content TEXT`           |
| <br />    | MEDIUMTEXT    | ≤ 16 MB                    | 更长文本      | `report MEDIUMTEXT`      |
| <br />    | LONGTEXT      | ≤ 4 GB                     | 超大文本      | —                        |
| **日期类型**  | DATE          | `1000-01-01` ~ `9999-12-31` | 日期（不含时分秒） | `birth_date DATE`        |
| <br />    | DATETIME      | `1000-01-01` ~ `9999-12-31` | **日期时间（推荐）** | `create_time DATETIME` |
| <br />    | TIMESTAMP     | `1970-01-01` ~ `2038-01-19` | 时间戳（有 2038 上限，谨慎使用） | `ts TIMESTAMP` |
| <br />    | TIME          | 时分秒                        | 仅时间       | `work_time TIME`         |
| **二进制类型** | VARBINARY(n)  | 变长二进制                      | 二进制数据     | `encrypt_data VARBINARY(255)` |
| <br />    | BLOB          | ≤ 64 KB                    | 二进制大对象    | `file_data BLOB`         |
| <br />    | JSON          | MySQL 5.7+ 原生 JSON         | 结构化扩展数据   | `ext_data JSON`          |

### 3.2 数据类型选择规范

| 业务场景   | 推荐类型      | 长度/精度 | 说明                        |
| ------ | --------- | ----- | ------------------------- |
| 主键ID   | CHAR      | 32    | 32 位无分隔符 UUID（优先）         |
| 顺序主键   | BIGINT    | -     | `AUTO_INCREMENT`，仅在需要顺序主键时使用 |
| 状态标记   | TINYINT   | -     | 0/1或小范围枚举值                |
| 排序号    | INT       | -     | 排序字段，少量数据或是无层级关系          |
| 排序编码   | INT       | -     | 排序字段，大量数据或是有层级关系          |
| 金额     | BIGINT    | -     | 以分为单位的长整数                 |
| 百分比    | DECIMAL   | (5,2) | 最大999.99%                 |
| 手机号    | VARCHAR   | 20    | 支持国际号码                    |
| 身份证号   | VARCHAR   | 18    | 中国身份证                     |
| 邮箱     | VARCHAR   | 100   | 邮箱地址                      |
| 姓名     | VARCHAR   | 50    | 用户姓名                      |
| 编码     | VARCHAR   | 32-50 | 业务编码（配 `as_cs` 排序规则）      |
| 标题     | VARCHAR   | 200   | 标题、名称                     |
| 描述     | VARCHAR   | 500   | 简短描述                      |
| 详细内容   | TEXT      | -     | 长文本、富文本                   |
| 日期     | DATE      | -     | 仅日期                       |
| 日期时间   | DATETIME  | -     | 完整时间（不使用 TIMESTAMP，避免 2038 上限） |
| JSON数据 | JSON      | -     | 结构化扩展字段（需兼容其他数据库时用 TEXT） |

### 3.3 类型使用注意事项

```sql
-- 正确示例
amount      BIGINT           COMMENT '金额（单位：分）'
create_time DATETIME         COMMENT '创建时间'
name        VARCHAR(50)      COMMENT '姓名'

-- 错误示例
amount      FLOAT            -- 禁止：金额使用浮点数会有精度问题
amount      DECIMAL(18,2)    -- 不推荐：金额统一用 BIGINT 存分
create_time VARCHAR(20)      -- 不推荐：时间存储为字符串
state       VARCHAR(10)      -- 不推荐：状态应使用 TINYINT 数值类型
id          VARCHAR(36)      -- 不推荐：32 位 UUID 应使用 CHAR(32) 定长
```

## 四、字典域和字典明细定义规范

### 4.1 字典表设计

参见[数据字典规范](数据字典规范.md)

### 4.2 字典域编码规范

| 规则项  | 规范要求           | 示例                        |
| ---- | -------------- | ------------------------- |
| 命名格式 | 大写字母，单词间用下划线分隔 | `C_STATUS`、`B_ORDER_STATUS` |
| 分类前缀 | 必须使用分类前缀，见下表    | `C_`/`S_`/`B_`             |
| 长度限制 | 不超过50个字符       | -                         |
| 语义明确 | 编码应能体现业务含义     | `B_GENDER`、`B_ORDER_STATUS` |

**分类前缀（与[数据字典规范](数据字典规范.md)保持一致，全项目唯一）**：

| 前缀 | 分类 | 定位 |
| --- | --- | --- |
| `C_` | 公用类（Common） | 跨业务通用，任何模块可直接引用 |
| `S_` | 系统类（System） | 技术/平台基础设施定义 |
| `B_` | 业务类（Business） | 具体业务领域定义 |

> **注意**：字典域编码禁止使用 `SYS_`、`BIZ_` 形式——该形式属于**表前缀**（见 1.1），不得用于字典域。字典域编码必须全局大写，且存储字段须使用 `utf8mb4_0900_as_cs` 排序规则以保证大小写敏感（见[项目规则](../project/项目规则.md)）。

### 4.3 字典项编码规范

| 规则项  | 规范要求                             | 示例                             |
| ---- | -------------------------------- | ------------------------------ |
| 命名格式 | 大写字母，单词间用下划线分隔                   | `PENDING`、`PAID`               |
| 编码类型 | 支持整型和字符串两种类型，常用为整型，部分业务可以采用字符串类型 | `0`/`1` 或 `ENABLED`/`DISABLED` |
| 长度限制 | 不超过50个字符                         | -                              |
| 排序规范 | 按业务逻辑排序                          | 状态流转顺序                         |

### 4.4 常用字典域定义

字典域与字典项的完整定义、编码规则、分类体系见[数据字典规范](数据字典规范.md)。本文不重复定义，避免两处维护产生歧义。

本数据库设计中固定引用的**公用类**字典域如下：

| 字典域编码 | 名称 | 适用字段 | 说明 |
| --- | --- | --- | --- |
| `C_STATUS` | 记录状态 | `state` | 0=无效，1=有效 |
| `C_DELETE_FLAG` | 逻辑删除标记 | `is_deleted` | 0=未删除，1=已删除 |
| `C_YES_NO` | 是否 | 通用二值字段 | 0=否，1=是 |

业务类字典域按业务模块定义，统一使用 `B_` 前缀，例如 `B_ORDER_STATUS`。

### 4.5 字典使用规范

```sql
-- 业务表中字典字段定义
CREATE TABLE biz_order (
    id              CHAR(32)     NOT NULL DEFAULT (REPLACE(UUID(), '-', '')) COMMENT '主键ID',
    order_no        VARCHAR(32)  NOT NULL COMMENT '订单编号',
    order_status    VARCHAR(20)  COLLATE utf8mb4_0900_as_cs NOT NULL COMMENT '订单状态(字典:B_ORDER_STATUS)',
    pay_type        VARCHAR(20)  COLLATE utf8mb4_0900_as_cs DEFAULT NULL COMMENT '支付方式(字典:B_PAY_TYPE)',
    state           TINYINT      NOT NULL DEFAULT 1 COMMENT '记录状态(字典:C_STATUS)',
    PRIMARY KEY (id)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci COMMENT = '业务订单表';

-- 查询时关联字典获取名称
SELECT
    o.id,
    o.order_no,
    o.order_status,
    o.state,
    di.item_name AS order_status_name,
    ds.item_name AS state_name
FROM biz_order o
LEFT JOIN sys_dict_item di
    ON di.domain_code = 'B_ORDER_STATUS'
    AND di.item_code = o.order_status
    AND di.state = 1
LEFT JOIN sys_dict_item ds
    ON ds.domain_code = 'C_STATUS'
    AND ds.item_code = o.state
    AND ds.state = 1;
```

## 五、索引设计规范

### 5.1 索引命名规范

| 索引类型 | 命名规则             | 示例                      |
| ---- | ---------------- | ----------------------- |
| 主键索引 | `pk_表名`（建表时直接用 `PRIMARY KEY`） | `pk_biz_order`          |
| 唯一索引 | `uk_表名_字段名`      | `uk_sys_user_username`      |
| 普通索引 | `idx_表名_字段名`     | `idx_biz_order_create_time` |
| 组合索引 | `idx_表名_字段1_字段2` | `idx_biz_order_state_time` |

### 5.2 索引设计原则

| 原则     | 说明              |
| ------ | --------------- |
| 选择性原则  | 选择性高的字段优先建索引    |
| 最左前缀原则 | 组合索引字段顺序按查询条件排列 |
| 适度原则   | 单表索引数量不超过5个     |
| 避免冗余   | 避免对低选择性字段单独建索引  |
| 前缀索引   | 长字符串字段可使用 `col(n)` 前缀索引控制索引长度 |
| 类型匹配   | 查询条件类型必须与索引列类型一致，避免隐式转换导致索引失效 |

### 5.3 索引创建语法

```sql
-- 建表时声明
CREATE TABLE biz_order (
    -- 字段定义略
    PRIMARY KEY (id),
    UNIQUE KEY uk_biz_order_no (order_no),
    KEY idx_biz_order_customer (customer_id),
    KEY idx_biz_order_state_time (state, create_time)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4;

-- 建表后追加
CREATE INDEX idx_biz_order_no ON biz_order(order_no);
ALTER TABLE biz_order ADD INDEX idx_biz_order_customer (customer_id);
```

## 六、SQL编写规范

### 6.1 SQL格式规范

```sql
-- 关键字大写，字段名小写
SELECT id, user_name, create_time
FROM sys_user
WHERE state = 1
ORDER BY create_time DESC;

-- 多表关联使用别名
SELECT u.id, u.user_name, d.dept_name
FROM sys_user u
LEFT JOIN sys_dept d ON u.dept_id = d.id
WHERE u.state = 1;

-- 复杂查询适当换行缩进
SELECT
    o.id,
    o.order_no,
    o.order_status,
    c.customer_name,
    COUNT(od.id) AS item_count,
    SUM(od.amount) AS total_amount
FROM biz_order o
INNER JOIN biz_customer c ON o.customer_id = c.id
LEFT JOIN biz_order_detail od ON o.id = od.order_id
WHERE o.state = 1
    AND o.order_status = 'PAID'
GROUP BY o.id, o.order_no, o.order_status, c.customer_name
HAVING SUM(od.amount) > 1000
ORDER BY o.create_time DESC;
```

### 6.2 SQL性能规范

| 规范项         | 要求                    |
| ----------- | --------------------- |
| 避免全表扫描      | WHERE条件使用索引字段         |
| 避免SELECT \* | 明确列出需要的字段             |
| 避免大事务       | 控制事务范围和时长             |
| 批量操作        | 使用批量INSERT/UPDATE     |
| 分页查询        | 使用 `LIMIT offset, size`；深度分页改用延迟关联或游标 |
| 避免隐式类型转换    | 字符串字段加引号，数值字段不加引号 |
| 避免函数包裹索引列   | `WHERE DATE(create_time) = ...` 会导致索引失效，改用范围条件 |
| 避免 OR 连接索引列 | 改用 `UNION ALL` 或 `IN` |

### 6.3 分页查询示例

```sql
-- 常规分页
SELECT id, order_no, create_time
FROM biz_order
WHERE state = 1
ORDER BY create_time DESC
LIMIT 0, 10;

-- 深度分页（延迟关联减少回表）
SELECT o.id, o.order_no, o.create_time
FROM biz_order o
INNER JOIN (
    SELECT id FROM biz_order WHERE state = 1 ORDER BY create_time DESC LIMIT 100000, 10
) t ON o.id = t.id;
```

### 7.1 MySQL 保留字与常用关键字

以下词语禁止作为表名或字段名（确需使用时必须加反引号）：

```
ADD, ALL, ALTER, AND, AS, ASC, BETWEEN, BY, CASE, COLUMN, CONDITION,
CREATE, CROSS, CURRENT_DATE, CURRENT_TIME, CURRENT_TIMESTAMP, DATABASE,
DEFAULT, DELETE, DESC, DISTINCT, DROP, ELSE, EXISTS, FALSE, FOR, FROM,
GROUP, HAVING, IN, INDEX, INNER, INSERT, INT, INTERVAL, INTO, IS, JOIN,
KEY, KEYS, LEFT, LIKE, LIMIT, LOAD, LOCK, LONG, MATCH, NOT, NULL, ON,
OPTIMIZE, OR, ORDER, OUTER, PRIMARY, RANGE, READ, REAL, RENAME, REPLACE,
RIGHT, SELECT, SET, SHOW, TABLE, THEN, TO, TRUE, UNION, UNIQUE, UNLOCK,
UPDATE, USAGE, USE, USER, USING, VALUES, WHEN, WHERE, WITH, WRITE, XOR,
ZEROFILL, STATUS, TYPE, ROWS, RANK, GROUPS, LEVEL, SIZE, COMMENT
```

> `STATUS`、`TYPE`、`KEY`、`RANGE`、`ROWS`、`RANK`、`LEVEL` 等词在 MySQL 8 中为保留字或常用关键字，建表时极易冲突，命名时应优先规避。

### 7.2 常用元数据查询

```sql
-- 查询当前库所有表及注释
SELECT TABLE_NAME, TABLE_COMMENT
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = DATABASE()
ORDER BY TABLE_NAME;

-- 查询表字段
SELECT COLUMN_NAME, COLUMN_TYPE, IS_NULLABLE, COLUMN_DEFAULT, COLUMN_COMMENT, COLLATION_NAME
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = DATABASE()
    AND TABLE_NAME = 'biz_order'
ORDER BY ORDINAL_POSITION;

-- 查询索引
SELECT INDEX_NAME, COLUMN_NAME, NON_UNIQUE, SEQ_IN_INDEX

WHERE TABLE_SCHEMA = DATABASE()
    AND TABLE_NAME = 'biz_order'
ORDER BY INDEX_NAME, SEQ_IN_INDEX;

-- 查看建表语句
SHOW CREATE TABLE biz_order;
```

### 7.3 建表检查清单

- [ ] 使用 `ENGINE = InnoDB DEFAULT CHARSET = utf8mb4`
- [ ] 表和全部字段均有 `COMMENT`
- [ ] 主键为 `CHAR(32)` UUID 或 `BIGINT AUTO_INCREMENT`
- [ ] 时间字段使用 `DATETIME`，`modify_time` 带 `ON UPDATE CURRENT_TIMESTAMP`
- [ ] 编码类字段显式指定 `COLLATE utf8mb4_0900_as_cs`
- [ ] 未使用保留字作为表名或字段名
- [ ] 外键字段与常用查询字段已建索引
- [ ] 金额字段为 `BIGINT`（单位：分），未使用浮点类型
