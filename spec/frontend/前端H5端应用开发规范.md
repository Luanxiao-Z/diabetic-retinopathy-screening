# 手机H5端和小程序端前端应用开发规范

## 1. 项目概述

### 1.1 技术栈

- **框架**: uni-app（Vue 3 版本）
- **语言**: TypeScript
- **状态管理**: Pinia
- **样式**: SCSS/Sass
- **UI 库**: uni-ui + uv-ui
- **构建工具**: Vite（HBuilderX 仅作为调试 IDE，不作为构建依赖）
- **包管理**: Yarn（与 PC 端保持一致）

### 1.2 项目结构

目录结构定义参见[前端H5端应用目录规划](前端H5端应用目录规划.md)。

### 1.3 与 PC 端的差异

| 维度 | PC 端（Web） | H5 / 小程序端 |
| --- | --- | --- |
| 框架 | Vue 3 + TypeScript | uni-app（Vue 3）+ TypeScript |
| 路由 | Vue Router 4.x | `pages.json` + uni 导航 API |
| 状态管理 | Pinia | Pinia |
| UI 库 | Element Plus | uni-ui + uv-ui |
| HTTP 客户端 | Axios | `uni.request` 封装 |
| 样式单位 | px / rem | rpx |

两端在**接口契约、状态管理、权限模型、编码风格**上保持一致，差异仅体现在路由、UI 组件与样式单位。

## 2. 编码规范

### 2.1 TypeScript 规范

- 所有新功能必须使用 TypeScript 编写。
- 变量和函数使用小驼峰：`userName`、`getUserInfo`
- 常量使用大写下划线分隔：`API_BASE_URL`、`MAX_RETRY_COUNT`
- 类型与接口使用帕斯卡命名法：`UserInfo`、`PageResult`
- 禁止使用 `any`，确需动态类型时使用 `unknown`。

```typescript
// 正确
const userName = '张三'
const API_BASE_URL = '/api/v1'

function getUserInfo({ id }: { id: string }): Promise<UserInfo> { ... }

// 错误
const user_name = '张三'
const apiBaseUrl = '/api/v1'
```

### 2.2 代码风格

- 使用 `const` 和 `let` 替代 `var`。
- 函数参数使用解构赋值。
- 使用箭头函数处理上下文。
- 使用模板字符串替代字符串拼接。

```typescript
// 正确
const formatUserName = ({ firstName, lastName }: UserName): string => {
  return `${firstName} ${lastName}`
}
```

### 2.3 Vue 组件规范

#### 2.3.1 组件结构

统一使用 `<script setup lang="ts">`：

```vue
<template>
  <view class="user-card">
    <!-- 模板内容 -->
  </view>
</template>

<script setup lang="ts">
interface Props {
  title: string
}

withDefaults(defineProps<Props>(), { title: '' })

const emit = defineEmits<{
  change: [value: string]

</script>

<style lang="scss" scoped>
.user-card { /* 样式 */ }
</style>
```

#### 2.3.2 组件命名

- 文件名使用帕斯卡命名法：`PageContainer.vue`、`ScreeningCard.vue`
- 组件名与文件名保持一致。
- 支持 `PascalCase` 与 `kebab-case` 两种使用形式。

#### 2.3.3 组件通信

- 父子通信: `props` 和 `emit`
- 兄弟通信: 通过父组件或 Pinia
- 跨层级通信: Pinia

### 2.4 样式规范

#### 2.4.1 SCSS 规范

- 使用 BEM 命名方法。
- 合理使用嵌套（不超过 3 层）。
- 使用变量管理颜色、字体等。

```scss
.user-card {
  padding: 24rpx;

  &__header {
    display: flex;

    &--large {
      font-size: 36rpx;
    }
  }
}
```

#### 2.4.2 尺寸单位

- 统一使用 `rpx` 适配不同屏幕尺寸（设计基准 750rpx）。
- H5 端会自动转换为 `rem`。
- 特殊情况可使用 `px`，但需注明原因。

## 3. 接口契约规范

H5 端与 PC 端共用同一套后端契约，类型定义必须与[后端应用开发规范](../backend/后端应用开发规范.md)一致。

### 3.1 统一响应类型

```typescript
/** 统一响应体 */
interface ApiResponse<T = unknown> {
  code: number
  msg: string
  data?: T
  errList?: string[]
  traceId?: string
}

/** 分页响应数据 */
interface PageResult<T> {
  total: number
  current: number
  pageSize: number
  list: T[]
}
```

> 注意：业务数据固定存放在 `data` 字段，不存在 `bizData` 等其他字段名。

### 3.2 请求封装

```typescript
// utils/http.ts
import { useUserStore } from '@/stores/user'

const BASE_URL = '/api/v1'

interface RequestOptions {
  url: string
  /** HTTP 方法，建议显式指定；缺省为 GET */
  method?: 'GET' | 'POST' | 'PUT' | 'PATCH' | 'DELETE'
  /** 请求参数；GET 时由 uni.request 自动拼接为 query string */
  data?: unknown
  header?: Record<string, string>
  loading?: boolean
}

export function request<T>(options: RequestOptions): Promise<T> {
  const userStore = useUserStore()

  if (options.loading) {
    uni.showLoading({ title: '加载中', mask: true })
  }

  return new Promise<T>((resolve, reject) => {
    uni.request({
      url: BASE_URL + options.url,
      method: options.method ?? 'GET',
      data: options.data,
      header: {
        'Content-Type': 'application/json;charset=UTF-8',
        'X-Access-Token': userStore.token,
        ...options.header
      },
      timeout: 30000,
      success: (res) => {
        const body = res.data as ApiResponse<T>
        if (body.code === 200) {
          resolve(body.data as T)
        } else {
          handleError(body)
          reject(body)
        }
      },
      fail: (err) => {
        uni.showToast({ title: '网络异常，请稍后重试', icon: 'none' })
        reject(err)
      },
      complete: () => {
        if (options.loading) uni.hideLoading()
      }
    })
  })
}

function handleError(body: ApiResponse) {
  // 401 清除登录态并跳转登录页；403 提示无权限；其余展示 msg
  uni.showToast({ title: body.msg || '请求失败', icon: 'none' })
}
```

约定：

- 接口统一前缀为 `/api/v1`，**禁止在代码中硬编码后端服务名**（如 `/portal-backend`）。
- 路径使用**资源名词复数**，不含任何操作动词；操作由 `method` 区分。
- 令牌统一存放在请求头 `X-Access-Token`，本地缓存键名为 `ACCESS_TOKEN`。
- `code === 200` 判定成功，其余为失败；`401` 清除登录态并跳转登录页。
- `loading` 由调用方按需开启，禁止全局默认开启遮罩。

**方法与参数**：`GET` 用于查询（参数由 `uni.request` 自动拼为 query string），
`POST` 用于新增、`PUT`/`PATCH` 用于更新、`DELETE` 用于删除（参数放在 `data` 中）。

### 3.3 API 模块化

```typescript
// apis/screening.ts
import { request } from '@/utils/http'
import type { PageResult, ScreeningRecord, ScreeningQuery, ScreeningCreateDTO } from '@/types/screening'

const BASE = '/biz/screening-records'

/** 分页查询 */
export const pageScreeningRecords = (params: ScreeningQuery & PageQuery) =>
  request<PageResult<ScreeningRecord>>({ url: BASE, method: 'GET', data: params, loading: true })

/** 查询详情 */
export const getScreeningRecord = (id: string) =>
  request<ScreeningRecord>({ url: `${BASE}/${id}`, method: 'GET' })

/** 新增 */
export const createScreeningRecord = (data: ScreeningCreateDTO) =>
  request<{ id: string }>({ url: BASE, method: 'POST', data })

/** 删除 */
export const deleteScreeningRecord = (id: string) =>
  request<void>({ url: `${BASE}/${id}`, method: 'DELETE' })
```

> **禁止**出现 `/screening-record/list`、`/screening-record/add` 这类 RPC 风格路径。

## 4. 本地存储规范

```typescript
// utils/storage.ts
export const storage = {
  set(key: string, value: unknown): Promise<void> {
    return new Promise((resolve, reject) => {
      uni.setStorage({ key, data: value, success: () => resolve(), fail: reject })
    })
  },
  get<T>(key: string): T | null {
    try {
      return uni.getStorageSync(key) as T
    } catch {
      return null
    }
  },
  remove(key: string): void {
    uni.removeStorageSync(key)
  }
}
```

- 存储键名统一在 `utils/constant.ts` 中定义为常量，禁止散落字面量。
- 令牌键名固定为 `ACCESS_TOKEN`。
- 禁止在本地存储患者隐私数据、密码等敏感信息。

## 6. 性能优化

### 6.1 图片优化

- 使用 WebP 格式。
- 合理压缩图片大小。
- 使用懒加载技术。
- 合理使用 SVG 图标。

### 6.2 组件优化

- 长列表使用虚拟滚动或 `scroll-view` 分页加载。
- 避免不必要的重渲染。
- 使用防抖和节流处理高频事件。

### 6.3 包体积优化

- 分包加载（小程序主包不超过 2MB）。
- Tree Shaking 移除无用代码。
- 第三方库按需引入。
- 图片资源压缩或使用 CDN。

## 8. 安全规范

### 8.1 数据安全

- 敏感数据加密存储。
- 接口参数验证（前后端均需校验，前端校验仅用于体验）。
- Token 有效期管理。
- 全程使用 HTTPS。

### 8.2 用户输入验证

- 前端基础验证。
- XSS 防护（禁止直接使用 `v-html` 渲染用户输入）。
- 所有输入在数据提交前由后端做最终校验，前端校验不可作为安全边界。
