# 目录规划

## 目录组织

```text
.                          # 项目根目录
├── README.md              # 项目说明文档
├── frontend/              # 前端代码目录（PC端 + H5端）
├── backend/               # 后端代码目录（Java / Spring Boot）
├── model-service/         # 模型服务目录（Python / 推理服务）
├── docs/                  # 项目文档目录
│   ├── requirements/      # 需求文档目录
│   └── design/            # 设计文档目录
├── models/                # 数据库模型目录
│   └── {项目名}.pdma.json # 数据库模型文档，符合 PDManer 格式
├── sql/                   # 数据库脚本目录
│   ├── init/              # 数据库初始化脚本目录
│   └── update/            # 数据库更新脚本目录，按日期升序命名
├── deploy/                # 部署与构建目录
│   ├── docker/            # 镜像构建目录（Dockerfile）
│   └── compose/           # 容器编排目录（docker-compose.yml、nginx 配置）
└── spec/                  # 开发规范目录（本目录）
    ├── project/           # 项目级规则与目录规划
    ├── backend/           # 后端规范
    ├── frontend/          # 前端规范
    └── design/            # 设计类规范
```

## 目录结构说明

| 目录 | 说明 | 参考规范 |
| --- | --- | --- |
| `frontend/` | 前端代码目录，包含 PC 端应用（`web/`）和 H5 端应用（`h5/`） | [PC端目录规划](../frontend/前端PC端应用目录规划.md)、[H5端目录规划](../frontend/前端H5端应用目录规划.md) |
| `backend/` | 后端代码目录，Java Spring Boot 多模块工程 | [后端应用目录规划](../backend/后端应用目录规划.md) |
| `model-service/` | 模型服务目录，Python 推理服务，独立于后端部署、可水平扩展 | [项目技术栈](../design/项目技术栈.md) |
| `models/` | 数据库模型目录，PDManer 模型文件（`.pdma.json`） | [数据模型文件格式说明](../design/数据模型文件格式说明.md) |
| `sql/` | 数据库脚本目录，由 PDManer 导出或人工维护，按日期升序执行 | [数据库设计规范](../design/数据库设计规范.md) |
| `deploy/` | 部署目录，镜像构建与容器编排 | [项目技术栈](../design/项目技术栈.md) |
| `spec/` | 开发规范目录，本目录内的规范对所有代码生效 | [项目规则](项目规则.md) |

## 命名约定

- 顶层目录使用小写英文单词，不使用下划线与大写字母。
- `sql/update/` 下的脚本命名格式：`{YYYYMMDD}_{序号}_{说明}.sql`，例如 `20260909_01_alter_screening_record.sql`。
- `models/` 下的模型文件名使用项目英文名的短横线形式，例如 `dr-screening.pdma.json`。
