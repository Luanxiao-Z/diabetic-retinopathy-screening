# 项目规则

本文件是项目级强制约束，效力高于各分项规范。分项规范与本文件冲突时，以本文件为准，并同步修正分项规范。

## 1. 通用约定

- 项目所有文件编码都应为 UTF-8（无 BOM）。
- 数据库统一使用 MySQL 8.x + InnoDB 引擎，字符集为 `utf8mb4`。
- 数据库默认排序规则为 `utf8mb4_0900_ai_ci`；**编码类字段（字典域编码、字典项编码、权限编码、业务编码）必须使用 `utf8mb4_0900_as_cs`**，即区分大小写。
- 因此所有编码类数据必须全局统一大小写，不得混用。
- 所有字典域编码必须是**大写字母 + 下划线**，例如 `C_STATUS`、`B_DR_LEVEL`。详见[数据字典规范](../design/数据字典规范.md)。

## 2. 构建与启动约定

- 启动前端和后端服务时，都需要先判断是否已经在运行，如果已经在运行则需要先停止。
- 前端后端服务启动出现端口被占用报错时，先尝试关闭已启动的服务，**不要直接修改前端和后端服务的端口号**。
- 不要尝试修改 Maven 本地依赖仓库存储路径。
- 项目内 Maven 多模块项目可编译出的模块依赖包不需要安装到本地依赖仓库。
- 执行后端应用编译命令时，需要先停止后端应用，避免本地依赖仓库安装失败。
- 通过 Maven 启动后端应用前需要先执行全量编译，编译失败则不执行启动应用。
- 使用 Maven 命令编译项目时，执行 `mvn clean compile` 命令，**不要执行 `mvn clean install` 命令**。
- 启动前端服务时，需要先启动后端服务（前端依赖后端接口与代理）。

## 3. 后端接口约定

- 后端接口服务路径以 `/api` 开头，版本号紧随其后，格式：`/api/v1/{安全场景前缀}/{资源路径}`。
- 接口一律遵循 **RESTful 规范**：路径中只允许出现资源名词（复数、小写、连字符分隔），**禁止任何操作动词或 RPC 风格动作名**；操作通过 HTTP 方法区分（`GET` 查询、`POST` 新增、`PUT`/`PATCH` 更新、`DELETE` 删除）。查询操作一律使用 `GET`，不得使用 `POST` 承载查询。
- 每个后端服务总是需要提供 Swagger 中文说明，包括接口路径、请求参数、响应参数、异常码等。
- 接口统一响应体为 `{ code, msg, data }`，`code` 为业务结果码；HTTP 状态码与 `code` 主段保持一致（新增成功为 `201`/`code=200`）。详见[后端应用开发规范](../backend/后端应用开发规范.md)。

## 4. 数据库约定

- 数据库规范中的示例数据不是项目实际使用的数据，仅用于说明数据库结构。
- 当前数据库可以正常连接时，优先以数据库中的数据为准，尤其是数据字典等配置类数据。
- 涉及数据库的操作可以先尝试使用 MySQL 对应的 MCP/客户端工具直接执行，只有数据库确实连接不上时才考虑仅提供脚本的方式。

## 6. 规范冲突处理原则

当多份规范对同一事项给出不同要求时，按以下优先级判定：

1. **本文件（项目规则）**
2. **数据库物理结构**：[数据库设计规范](../design/数据库设计规范.md) 为物理库事实标准；[数据模型规范](../design/数据模型规范.md) 描述的是 PDManer 模型侧定义，两者通过大小写映射规则对应（模型侧大写，物理库小写）。
3. **接口契约**：[后端应用开发规范](../backend/后端应用开发规范.md) 定义的响应体结构为前后端唯一契约，前端规范中的类型定义必须与其一致。
4. **权限编码**：[后端API权限控制规范](../design/后端API权限控制规范.md) 与 [前端页面权限控制规范](../design/前端页面权限控制规范.md) 必须使用同一套权限编码体系。
