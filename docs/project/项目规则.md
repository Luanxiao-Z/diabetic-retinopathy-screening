# 项目规则

本文件是项目级强制约束，效力高于各分项规范。分项规范与本文件冲突时，以本文件为准，并同步修正分项规范。

## 1. 通用约定

- 项目所有文件编码为 UTF-8（无 BOM）；`model-service/requirements.txt` 保持纯 ASCII，避免中文 Windows 下 pip 以 GBK 解码报错。
- 数据库使用 MySQL 8.x + InnoDB，字符集 `utf8mb4`，默认排序规则 `utf8mb4_0900_ai_ci`。
- **编码类字段**（字典域编码、字典项编码、权限编码、业务编码）使用 `utf8mb4_0900_as_cs`，即区分大小写；编码类数据必须全局统一大小写，不得混用。
- 字典域编码使用大写字母 + 下划线，例如 `C_STATUS`、`B_DR_SUGGESTION`。详见[数据字典规范](../design/数据字典规范.md)。
- 凭据（数据库、Redis、Silo）一律通过环境变量注入，不得写入版本库或文档明文。
- 提交信息遵循 Conventional Commits，不添加任何协作者署名行。

## 2. 构建与启动约定

- 后端工程使用 Maven 多模块；构建产物为 `drs-app-server` 的 fat-jar。执行 `mvn clean` 前需先停止占用 8080 端口的后端进程，否则无法删除 `target` 目录。
- Windows 下请用 PowerShell 调用原生 `mvn.cmd`；`-DskipTests` 需通过 `$env:MAVEN_OPTS` 传入，直接写在命令行中会被 PowerShell 剥离。
- 前端包管理器统一使用 Yarn，不混用 npm，避免 lock 文件冲突。
- 模型服务使用 **Python 3.13+** 创建的 `.venv`；其 Python 版本必须与 torch 轮子的 cp313 ABI 匹配，否则 `import torch` 会因 C 扩展加载失败而报错。
- 训练必须使用 `python -m training.train`（直接执行脚本路径会报 `No module named 'app'`）。

## 3. 后端接口约定

- 接口路径以 `/api/v1` 开头，格式为 `/api/v1/{场景前缀}/{资源路径}`；路径只含资源名词，操作由 HTTP 方法表达，查询一律使用 `GET`。
- 每个接口需提供 Knife4j 中文说明，包括路径、请求参数、响应参数与异常码。
- 统一响应体为 `{ code, msg, data }`，`code` 为业务结果码。**业务异常维持 HTTP 200 + 信封 `code`**；仅 `401` / `403` 同时返回对应 HTTP 状态码。详见[后端应用开发规范](../backend/后端应用开发规范.md)。
- 分页参数统一为 `current`（从 1 开始）与 `pageSize`（默认 10），不使用 `pageNum`。
- 认证采用 UUID Token + Redis Session，请求头为 `X-Access-Token`；匿名接口统一置于 `/api/v1/auth/` 前缀下。
- 权限采用轻量化角色映射（ADMIN / DOCTOR）+ 数据范围（ALL / SELF），不建 RBAC 表。
- 响应体时间字段序列化为 `yyyy-MM-dd HH:mm:ss`；仅面向排障的操作日志保留 ISO8601 写法。

## 4. 数据库约定

- 建表与字典初始化脚本集中在 `sql/init/`，采用幂等写法，可重复执行完成升级。
- 项目未启用 `MetaObjectHandler` 自动填充：新建实体必须显式设置 `id`、`deleteFlag`、`createTime`、`updateTime`，否则会触发 `Column 'id' cannot be null`。
- `updateById` 无法把字段更新为 `null`（字段策略 `NOT_NULL`）；需要清空字段时必须使用 `LambdaUpdateWrapper` 显式 `.set(...)`。
- `Map.of(...).get(null)` 会抛 NPE；名称映射查询使用空安全的 `nameOf(...)`。
- 人工复核判定依据是**归一化预测熵** `uncertainty`（阈值 0.15，`≥` 阈值需复核），不是 top1 置信度；`confidence` 仅作展示。阈值与模型绑定，重训模型后必须重新标定（标定脚本为一次性实验工具，未随仓库分发；更换模型后需重新拟合，当前 0.15 与现版模型绑定）。

## 6. 规范冲突处理原则

当多份规范对同一事项给出不同要求时，按以下优先级判定：

1. **本文件（项目规则）**；
2. **实际代码实现**：以仓库内源码与 `sql/init/` 脚本为准，文档表述不得与实现相悖；
3. **接口契约**：[后端应用开发规范](../backend/后端应用开发规范.md) 定义的响应体结构为前后端唯一契约，前端类型定义必须与其一致；
4. **权限编码**：[后端API权限控制规范](../design/后端API权限控制规范.md) 与 [前端页面权限控制规范](../design/前端页面权限控制规范.md) 必须使用同一套权限编码体系。
