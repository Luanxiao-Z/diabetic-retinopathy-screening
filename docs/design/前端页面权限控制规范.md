# 前端页面权限控制规范

## 1. 目的与适用范围

本规范定义前端（PC 端 Web 应用与 H5 / 小程序端应用）的页面级与元素级权限控制方案，覆盖从路由准入到按钮显隐的完整链路。

- 配套规范：[后端API权限控制规范](后端API权限控制规范.md)（后端 Filter 链与 `@RequirePermission`）
- 权限编码在前后端**必须完全一致**，后端为权威来源。
- 本规范为强制约束，新增页面、菜单、按钮时必须遵循。

## 2. 权限模型

### 2.1 三级权限模型

```
模块（Module）→ 页面（Page）→ 功能（Function）
```

| 层级 | 说明 | 示例 |
| --- | --- | --- |
| 模块 | 用于菜单分层，本身不控制访问 | 系统管理、业务中心 |
| 页面 | 菜单节点级，控制路由准入 | 用户管理、角色管理 |
| 功能 | 页面内某一类操作入口，控制元素显隐 | 查询、编辑、分配权限 |

### 2.2 权限编码格式

```
{模块}:{页面}:{操作}
```

- 全部小写，使用冒号分隔，禁止大写与下划线。
- 示例：`sys:user:list`、`sys:user:edit`、`sys:role:assign-perm`。

### 2.3 权限精简原则（核心）

**同类操作合并**：对页面主体数据的增、删、改、禁、启等修改类操作，合并为一个 `edit` 权限。

**关联数据独立**：只有操作的是**与主体不同的关联数据**时，才定义为独立的操作权限。

判断标准：操作的是页面的**主体数据**还是**关联数据**。

- 主体数据 → 合并到 `edit`
- 关联数据 → 独立定义权限

| 权限编码 | 含义 | 说明 |
| --- | --- | --- |
| `sys:user:list` | 用户管理-查询 | 查看用户列表和详情 |
| `sys:user:edit` | 用户管理-编辑 | 新增、修改、删除、禁用、启用用户（主体数据修改合并） |
| `sys:role:list` | 角色管理-查询 | 查看角色列表和详情 |
| `sys:role:edit` | 角色管理-编辑 | 新增、修改、删除、禁用、启用角色 |
| `sys:role:assign-perm` | 角色管理-分配权限 | 操作关联数据（权限），独立定义 |
| `sys:role:assign-user` | 角色管理-分配用户 | 操作另一种关联数据（用户），独立定义 |

**禁止的写法**（过度细分）：

- ~~`sys:user:add`~~、~~`sys:user:delete`~~、~~`sys:user:disable`~~、~~`sys:user:enable`~~ → 一律合并为 `sys:user:edit`

## 3. 权限数据流

```
后端接口 GET /api/v1/common/users/me/permissions
        │  返回当前用户权限编码列表
        ▼
Pinia usePermissionStore（内存）
        │
        ├──> 路由守卫：校验页面级权限（meta.permission）
        ├──> 动态路由/菜单：过滤无权限菜单
        └──> v-permission 指令 / hasPermission()：控制元素显隐
```

### 3.1 权限查询接口

- 接口：`GET /api/v1/common/users/me/permissions`
- HTTP 方法：`GET`（查询语义，不得使用 `POST`）
- 归属：`/api/v1/common/**` 前缀（需登录令牌，无需功能权限），见[后端API权限控制规范](后端API权限控制规范.md)。
- 响应：`data` 为权限编码字符串数组。

> 路径遵循 RESTful 规范：`users/me/permissions` 表示"当前登录用户的权限"这一从属资源；`me` 为指代当前登录用户的约定写法。

```typescript
// 响应示例
{
  "code": 200,
  "msg": "成功",
  "data": ["sys:user:list", "sys:user:edit", "sys:role:list"]
}
```

### 3.2 刷新时机

| 时机 | 行为 |
| --- | --- |
| 登录成功后 | 立即拉取并缓存 |
| 应用刷新（F5） | 若本地存在有效令牌则重新拉取 |
| 退出登录 | 清空权限缓存 |
| 切换当前机构/角色（如支持） | 重新拉取 |

## 4. TypeScript 类型定义

```typescript
/** 权限项 */
interface PermissionItem {
  /** 权限编码，如 sys:user:edit */
  code: string
  /** 权限名称 */
  name: string
  /** 权限类型：MODULE-模块 / PAGE-页面 / FUNCTION-功能 */
  type: 'MODULE' | 'PAGE' | 'FUNCTION'
}

/** 权限树节点（用于权限配置界面） */
interface PermissionTreeNode extends PermissionItem {
  children?: PermissionTreeNode[]
}

/** 权限 Store 状态 */
interface PermissionState {
  /** 当前用户权限编码集合 */
  codes: Set<string>
  /** 是否已加载 */
  loaded: boolean
}
```

## 5. PC 端实现规范

### 5.1 权限 Store

```typescript
// stores/permission.ts
import { defineStore } from 'pinia'
import { computed, ref } from 'vue'
import { fetchPermissions } from '@/apis/permission'

export const usePermissionStore = defineStore('permission', () => {
  const codes = ref<Set<string>>(new Set())
  const loaded = ref(false)

  const hasPermission = (code?: string | string[]): boolean => {
    if (!code || (Array.isArray(code) && code.length === 0)) return true
    const list = Array.isArray(code) ? code : [code]
    return list.some((c) => codes.value.has(c))
  }

  async function loadPermissions() {
    const data = await fetchPermissions()
    codes.value = new Set(data)
    loaded.value = true
  }

  function reset() {
    codes.value.clear()
    loaded.value = false
  }

  return { codes, loaded, hasPermission, loadPermissions, reset }
})
```

### 5.2 路由配置

- 路由 `meta.permission` 声明进入该页面所需的权限编码（字符串或字符串数组）。
- 无需权限即可访问的页面（首页、个人中心、404）**不声明** `meta.permission`。
- 白名单路由（登录页等）在 `meta.whiteList` 中标记。

```typescript
{
  path: '/system/user',
  name: 'SystemUser',
  component: () => import('@/views/system/user/index.vue'),
  meta: { title: '用户管理', permission: 'sys:user:list' }
}
```

### 5.3 路由守卫

`router.beforeEach` 中的判定顺序**不可调整**：

1. 命中白名单 → 直接放行
2. 未登录（无有效令牌）→ 跳转登录页并携带 `redirect` 参数
3. 权限未加载 → 先加载权限，加载失败则跳转登录页
4. 目标路由声明了 `meta.permission` 且当前用户不具备 → 跳转 403 页面
5. 其余情况放行

```typescript
router.beforeEach(async (to, _from, next) => {
  const userStore = useUserStore()
  const permStore = usePermissionStore()

  if (to.meta.whiteList) return next()
  if (!userStore.isLoggedIn) return next({ path: '/login', query: { redirect: to.fullPath } })

  if (!permStore.loaded) {
    try {
      await permStore.loadPermissions()
    } catch {
      return next({ path: '/login' })
    }
  }

  if (!permStore.hasPermission(to.meta.permission as string | string[])) {
    return next({ path: '/403' })
  }
  next()
})
```

### 5.4 元素级权限控制

统一使用 `v-permission` 指令，禁止在模板中直接访问 Store 做权限判断。

```typescript
// directives/permission.ts
import type { Directive } from 'vue'
import { usePermissionStore } from '@/stores/permission'

export const permission: Directive<HTMLElement, string | string[]> = {
  mounted(el, binding) {
    const store = usePermissionStore()
    if (!store.hasPermission(binding.value)) {
      el.parentNode?.removeChild(el)
    }
  }
}
```

```vue
<!-- 使用 -->
<el-button v-permission="'sys:user:edit'">新增</el-button>
<el-button v-permission="['sys:role:assign-perm', 'sys:role:edit']">配置</el-button>
```

> 说明：指令采用**移除 DOM** 而非隐藏，避免通过开发者工具绕过。

### 5.5 菜单过滤

- 菜单由后端返回或前端静态定义，渲染前根据权限过滤。
- 过滤逻辑统一封装在 `utils/permission.ts` 的 `filterMenu` 中。
- 过滤后若某个模块下无任何可见页面，则该模块也不展示。

## 6. H5 端实现规范

### 6.1 技术差异

| 维度 | PC 端 | H5 / 小程序端 |
| --- | --- | --- |
| 路由 | Vue Router + `beforeEach` | `pages.json` + `uni.addInterceptor` |
| 状态管理 | Pinia | Pinia |
| 元素控制 | `v-permission` 指令 | `v-if` + `hasPermission()` |

### 6.2 页面拦截器

```typescript
// 在 main.ts 中注册，拦截 navigateTo / redirectTo / switchTab / reLaunch
const PERMISSION_WHITE_LIST = ['/pages/public/login', '/pages/exception/403']

uni.addInterceptor('navigateTo', {
  invoke(args: { url: string }) {
    return checkPagePermission(args.url)
  }
})

function checkPagePermission(url: string): boolean {
  const path = url.split('?')[0]
  const userStore = useUserStore()
  const permStore = usePermissionStore()

  if (PERMISSION_WHITE_LIST.includes(path)) return true
  if (!userStore.isLoggedIn) {
    uni.redirectTo({ url: `/pages/public/login?redirect=${encodeURIComponent(url)}` })
    return false
  }
  const required = getPagePermission(path) // 从页面权限映射表中获取
  if (required && !permStore.hasPermission(required)) {
    uni.redirectTo({ url: '/pages/exception/403' })
    return false
  }
  return true
}
```

### 6.3 页面权限映射表

H5 端无路由 meta，需在 `config/pagePermission.ts` 中集中声明：

```typescript
export const PAGE_PERMISSION_MAP: Record<string, string> = {
  '/pages/system/user/index': 'sys:user:list',
  '/pages/system/role/index': 'sys:role:list'
}
```

新增页面必须同步登记，未登记的页面视为无需权限。

### 6.4 元素级权限控制

```vue
<template>
  <button v-if="hasPermission('sys:user:edit')">新增</button>
</template>

<script setup lang="ts">
import { usePermissionStore } from '@/stores/permission'
const { hasPermission } = usePermissionStore()
</script>
```

## 7. 六种场景处理规范

| 场景 | 控制方式 | PC 端实现 | H5 端实现 |
| --- | --- | --- | --- |
| 1. 未登录页面（登录页） | 路由白名单 | `meta.whiteList` | `PERMISSION_WHITE_LIST` |
| 2. 登录后页面（首页） | 仅需登录态 | 守卫第 2 步校验令牌 | 拦截器校验令牌 |
| 3. 查看权限 | 页面级权限 | `meta.permission` = `xxx:list` | 映射表 = `xxx:list` |
| 4. 修改权限 | 元素级权限 | `v-permission="'xxx:edit'"` | `v-if="hasPermission('xxx:edit')"` |
| 5. 操作权限（关联数据） | 元素级权限 | `v-permission="'xxx:assign-yyy'"` | `v-if="hasPermission(...)"` |
| 6. 权限配置 | 三级权限树 + 后端接口 | 权限树组件 + `sys:role:assign-perm` | 一般不提供 |

## 8. 与后端的协作约定

| 约定项 | 要求 |
| --- | --- |
| 编码一致性 | 前端使用的权限编码必须存在于后端 `@RequirePermission` 清单中 |
| 校验层次 | 前端控制仅用于体验，**后端必须独立校验**，不得依赖前端隐藏 |
| 401 处理 | 前端收到 `code=401` 清除登录态并跳转登录页 |
| 403 处理 | 前端收到 `code=403` 提示无权限，不做跳转 |
| 编码变更 | 后端新增/废弃权限编码需同步通知前端更新 |

## 9. 检查清单

新增页面或功能时，逐项确认：

- [ ] 页面已在路由（PC）或 `PAGE_PERMISSION_MAP`（H5）中声明所需权限
- [ ] 权限编码遵循精简原则（主体数据修改合并为 `edit`）
- [ ] 权限编码与后端 `@RequirePermission` 完全一致
- [ ] 页面内所有操作按钮均已做元素级权限控制
- [ ] 菜单已按权限过滤
- [ ] 未登录/无权限场景均有明确的用户提示或跳转
- [ ] 后端对该接口已独立做权限校验（前端控制不可替代后端校验）
