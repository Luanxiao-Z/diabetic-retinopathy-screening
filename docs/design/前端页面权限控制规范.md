# 前端页面权限控制规范

## 1. 目的与适用范围

本规范定义前端 PC 端 Web 应用的路由准入与元素级权限控制。

- 配套规范：[后端API权限控制规范](后端API权限控制规范.md)（`AuthFilter` + `@RequirePermission`）
- 权限编码前后端**必须完全一致**，后端 `PermissionConstants` 为权威来源
- 本项目采用**轻量化角色映射**（ADMIN / DOCTOR），不建 RBAC 表、不维护权限树、不做动态路由

## 2. 权限模型

### 2.1 模型

角色在登录后由后端下发权限集，前端只做**显隐控制与路由提示**，不参与权限判定逻辑：

| 角色 | 数据范围 | 权限集要点 |
| --- | --- | --- |
| `ADMIN` | `ALL` | 用户/字典/日志管理 + 全部筛查业务权限 |
| `DOCTOR` | `SELF` | `common:dict:view` + 全部 `biz:screening:*` |

权限编码全部小写、以冒号分段，例如 `admin:user:edit`、`biz:screening:review`。完整清单见[后端API权限控制规范](后端API权限控制规范.md)第五节。

### 2.2 编码精简原则

统计、待办、患者随访等查询类能力**复用** `biz:screening:view`，不单独定义编码；同类修改类操作合并为一个 `edit`。禁止按按钮逐个定义编码。

## 3. 权限数据流

```
登录成功 → 后端返回 token / role / permissions / dataScope
        │
        ▼
useUserStore（localStorage 保存 token，内存保存角色与权限集）
        │
        ├──> router.beforeEach：校验登录态与路由 meta.permission
        └──> v-permission 指令：控制按钮等元素显隐
```

- 登录接口：`POST /api/v1/auth/sessions`，除图形验证码外还需 `captchaKey` / `captchaCode`。
- 令牌保存在 `localStorage` 的 `token` 键；请求统一通过 `utils/request.ts` 拦截器注入 `X-Access-Token`。
- 退出登录时清空 `token` 与用户信息，并调用 `DELETE /api/v1/auth/sessions`。

## 4. 路由准入

路由集中在 `src/router/index.ts` 静态定义，`meta` 中声明：

| 字段 | 含义 |
| --- | --- |
| `meta.public` | 白名单页面（登录、注册、403 等），无需登录即可访问 |
| `meta.permission` | 进入该页面所需的权限编码 |
| `meta.title` | 浏览器标题，由守卫统一设置 |

`router.beforeEach` 的判定顺序：

1. 命中 `meta.public` → 直接放行；
2. 未登录（无有效令牌）→ 跳转登录页并携带 `redirect`；
3. 目标路由声明了 `meta.permission`，且权限集已加载、但不包含该编码 → 跳转 403；
4. 其余情况放行。

> **注意**：刷新后权限集尚未拉取时不拦截，避免误跳转；权限就绪后由 `v-permission` 控制按钮显隐。

## 5. 元素级权限控制

统一使用 `v-permission` 指令，禁止在模板中直接访问 Store 做权限判断。

```typescript
// src/directives/permission.ts
const codes = Array.isArray(binding.value) ? binding.value : [binding.value]
const has = codes.some((c) => userStore.permissions.includes(c))
```

用法：

```vue
<el-button v-permission="'admin:user:edit'">编辑</el-button>
<el-button v-permission="['biz:screening:review', 'biz:screening:edit']">复核</el-button>
```

- 支持字符串或数组，数组表示**满足其一即可**。
- 指令按当前登录用户的权限集决定元素显隐；权限不足时移除元素。
- 前端控制仅用于体验，**后端必须独立校验**，不得依赖前端隐藏。

## 6. 与后端的协作约定

| 约定项 | 要求 |
| --- | --- |
| 编码一致性 | 前端使用的权限编码必须存在于后端 `PermissionConstants` |
| 校验层次 | 后端独立校验，前端控制不可替代后端校验 |
| 401 处理 | 请求拦截器收到 `code=401` 清除登录态并跳转登录页 |
| 403 处理 | 提示无权限或跳转 403 页面 |
| 编码变更 | 后端新增/废弃编码需同步更新前端声明 |

## 7. 检查清单

新增页面或功能时，逐项确认：

- [ ] 路由已在 `src/router/index.ts` 声明 `meta.title`，需要权限时声明 `meta.permission`
- [ ] 公开页面已声明 `meta.public`
- [ ] 权限编码遵循精简原则，且与后端 `@RequirePermission` 完全一致
- [ ] 页面内所有受控操作按钮均已使用 `v-permission`
- [ ] 后端对该接口已独立做权限与数据范围校验
