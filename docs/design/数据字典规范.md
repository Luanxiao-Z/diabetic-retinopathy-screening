# 数据字典规范

## 一、概述

本规范定义本项目数据字典的分类、编码、表结构和使用方式，确保后端、模型服务与前端对枚举值的理解一致。

> **相关规范**：数据库表/字段命名与类型选择见 [数据库设计规范](./数据库设计规范.md)；建表脚本见 `sql/init/01_init_dr_screening.sql`。

### 1.1 适用范围

- 后端 `drs-module-system` 的字典查询与维护接口；
- 前端下拉框、标签、状态展示与中文名称映射；
- `sql/init/` 中的字典初始化数据。

### 1.2 术语

| 术语 | 含义 |
| --- | --- |
| 字典域 | 一组同类枚举值的集合，对应 `sys_dict_domain` 一行 |
| 字典项 | 域内的一个可选值，对应 `sys_dict_item` 一行 |
| `domain_code` | 字典域编码，全局唯一 |
| `item_code` | 字典项编码，域内唯一 |

## 二、分类与编码规范

### 2.1 分类

字典域编码采用**大写字母 + 下划线**，由前缀区分类别：

| 前缀 | 类别 | 说明 | 本项目示例 |
| --- | --- | --- | --- |
| `C_` | 公用类 | 跨业务复用的基础枚举 | `C_STATUS`、`C_YES_NO`、`C_DELETE_FLAG`、`C_GENDER` |
| `B_` | 业务类 | 与具体业务绑定的枚举 | `B_USER_ROLE`、`B_DR_LEVEL`、`B_DR_SUGGESTION` |

> 本项目未使用树形字典：字典项之间无父子层级，`sys_dict_item` 不含 `parent_code` 字段。

### 2.2 编码规则

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| `domain_code` | `{前缀}_{语义}`，全大写下划线 | `B_DR_SUGGESTION` |
| `item_code` | 大写枚举值，可与业务代码常量一致 | `ENABLED`、`LEVEL_3`、`REFERRAL` |
| `item_name` | 面向用户的中文名称 | `启用`、`重度 NPDR`、`需转诊` |
| `item_value` | 可选的扩展值（如展示色值），无则留空 | `#E6A23C` |
| `sort` | 展示顺序，从小到大 | `1`、`2`、`3` |

- 编码类字段使用 `utf8mb4_0900_as_cs` 排序规则，**区分大小写**，因此编码必须全局统一大小写，不得混用。
- `item_code` 直接对应后端常量与前端类型字面量（如 `SysUserEntity.role` 的 `DOCTOR` / `ADMIN`），不得另造别名。

## 三、表结构

### 3.1 字典域表 `sys_dict_domain`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | `CHAR(32)` | 主键 | 32 位无分隔符 UUID |
| `domain_code` | `VARCHAR(64)` | 唯一，`as_cs` | 字典域编码 |
| `domain_name` | `VARCHAR(128)` | 非空 | 中文名称 |
| `remark` | `VARCHAR(255)` | 可空 | 备注 |
| `create_by` / `create_time` | — | — | 创建审计字段 |
| `update_by` / `update_time` | — | — | 更新审计字段，`update_time` 由 `ON UPDATE CURRENT_TIMESTAMP` 维护 |
| `delete_flag` | `VARCHAR(1)` | 默认 `N`，`as_cs` | 逻辑删除标记 |

### 3.2 字典项表 `sys_dict_item`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | `CHAR(32)` | 主键 | 32 位无分隔符 UUID |
| `domain_code` | `VARCHAR(64)` | 联合唯一，`as_cs` | 所属字典域 |
| `item_code` | `VARCHAR(64)` | 联合唯一，`as_cs` | 字典项编码 |
| `item_name` | `VARCHAR(128)` | 非空 | 中文名称 |
| `item_value` | `VARCHAR(255)` | 可空 | 扩展值 |
| `sort` | `INT` | 默认 0 | 展示顺序 |
| `remark` / 审计字段 / `delete_flag` | — | — | 同字典域表 |

唯一约束：`uk_domain_item (domain_code, item_code)`；另有 `idx_domain_code` 索引。

## 四、本项目字典清单

`sql/init/01_init_dr_screening.sql` 初始化 **7 个字典域、18 个字典项**，使用 `INSERT ... ON DUPLICATE KEY UPDATE` 保证幂等：

| 域编码 | 名称 | 字典项 |
| --- | --- | --- |
| `B_USER_ROLE` | 用户角色 | `DOCTOR`（医生）、`ADMIN`（管理员） |
| `B_DR_LEVEL` | DR 分级 | `LEVEL_0` ~ `LEVEL_4`（正常 / 轻度 / 中度 / 重度 / 增殖期） |
| `B_DR_SUGGESTION` | 转诊建议 | `REVIEW`（复查）、`CLINIC`（门诊）、`REFERRAL`（转诊） |
| `C_STATUS` | 通用状态 | `ENABLED`（启用）、`DISABLED`（停用） |
| `C_YES_NO` | 是否 | `Y`（是）、`N`（否） |
| `C_DELETE_FLAG` | 删除标记 | `N`（未删除）、`Y`（已删除） |
| `C_GENDER` | 性别 | `MALE`（男）、`FEMALE`（女） |

> 分级映射：`LEVEL_0/1 → REVIEW`、`LEVEL_2 → CLINIC`、`LEVEL_3/4 → REFERRAL`。分级名称与颜色由前端 `types/screening.ts` 常量与 `LEVEL_COLOR` 提供，字典表用于后台维护与统一查询。

## 五、使用规范

### 5.1 业务表引用字典

- 业务表字段存储 `item_code`（如 `sys_user.role`、`sys_user.status`、`biz_screening_record.result_level`），不存中文名称。
- 展示层通过字典查询接口把编码转换为 `item_name`；名称映射查询必须使用空安全的 `nameOf(...)`，避免 `Map.of(...).get(null)` 抛 NPE。
- 不得在业务代码里硬编码中文名称作为判定条件。

### 5.2 查询与维护接口

| 接口 | 说明 |
| --- | --- |
| `GET /api/v1/common/dicts` | 查询字典域列表 |
| `GET /api/v1/common/dicts/{code}/items` | 查询指定域的字典项（按 `sort` 升序） |
| `/api/v1/admin/dict-domains` 系列 | 管理员维护字典域与字典项（增删改、排序、级联删除） |

- 字典查询属于 `/api/v1/common/**`，需登录但不要求功能权限。
- 字典维护属于 `/api/v1/admin/**`，需要 `admin:dict:edit` 权限。

### 5.3 前端展示

- 下拉框、标签、状态列统一按 `sort` 升序渲染。
- 未匹配到字典项的编码应回退显示原始编码或占位符，不得显示空白；Jackson 配置为 `non_null`，前端类型需按可选字段处理。
- 概率等数值展示保留一位小数，极小值显示 `<0.1%`，不得用 `Math.round` 造成 0% / 100% 的硬分类假象。

## 六、新增字典的约定

1. 在 `sql/init/01_init_dr_screening.sql` 中按幂等写法插入域与项，编码遵循第二节规则。
2. 后端新增对应常量或类型定义，确保 `item_code` 与代码中的字面量一致。
3. 前端补充类型联合与展示映射，并在下拉/标签处接入字典查询。
4. 若该字典用于筛选条件，需在对应分页查询 DTO 中补充字段并在 Service 层拼接查询条件。
