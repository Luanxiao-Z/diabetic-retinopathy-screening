# 项目技术栈

本项目是采用 **MIT 协议**开源的医学人工智能学习项目，技术选型以「可运行、可复现、依赖精简」为原则。本文件定义各层的选型与版本约束，引入清单外的新依赖需评估并更新本文件。

## 后端技术栈

| 领域 | 选型 | 版本/说明 |
| --- | --- | --- |
| 运行时 | JDK | 21（LTS） |
| 框架 | Spring Boot | 3.4.4（基于 Jakarta EE 命名空间） |
| 构建 | Maven | 3.9.x 多模块聚合，版本由 `drs-dependencies-bom` 统一管理 |
| 数据库 | MySQL | 8.x，InnoDB 引擎，字符集 `utf8mb4`，默认排序规则 `utf8mb4_0900_ai_ci` |
| 对象映射 | MyBatis-Plus | 3.5.11，分页与条件构造器使用其内置能力 |
| 缓存 / 会话 | Redis 7 + Jedis 5.2.0 | UUID Token 会话，非 JWT；统一端口 26379 |
| 对象存储 | **Silo**（MinIO 兼容 fork） | S3 协议，MinIO Java SDK 8.5.7 访问私有桶 `dr-screening`；沿用 `MINIO_*` 环境变量 |
| 接口文档 | Knife4j | 4.5.0（Swagger / OpenAPI 3），所有接口提供中文说明 |
| 验证码 | easy-captcha | 图形验证码，文本存 Redis 且一次性消费 |
| 报表导出 | Apache POI | Excel 导出 |
| 日志门面 / 实现 | SLF4J / Logback | 第三方日志统一桥接至 Logback |
| 安全框架 | 不引入 Spring Security | 自定义 `AuthFilter` + `PermissionInterceptor`，见[后端API权限控制规范](后端API权限控制规范.md) |

> **审计字段**：项目未启用 MyBatis-Plus 的 `MetaObjectHandler` 自动填充。新建实体必须显式设置 `id`、`deleteFlag`、`createTime`、`updateTime`；`update_time` 由数据库 `ON UPDATE CURRENT_TIMESTAMP` 维护。

## 模型服务技术栈

| 领域 | 选型 | 说明 |
| --- | --- | --- |
| 语言 | Python 3.13+ | 推荐 3.13，与 `torch` 的 cp313 轮子匹配 |
| 框架 | FastAPI + Uvicorn | 提供 HTTP 推理接口 |
| 深度学习 | PyTorch 2.14.0 + torchvision 0.29.0 | 默认 CUDA cu130 轮子；无 NVIDIA GPU 时改用 `+cpu` 轮子，服务支持 CPU 回退 |
| 骨干网络 | MobileNetV3-Small | 5 类分类头 |
| 权重格式 | PyTorch 状态字典（`.pth`） | `model-service/models/best_model.pth`，已纳入版本控制 |
| 可解释性 | 自实现 Grad-CAM | 生成热力图 PNG |

## 依赖引入原则

1. **最小依赖**：优先使用 JDK 与 Spring Boot 自带能力，避免引入功能重叠的库。
2. **统一版本**：依赖版本在 `drs-dependencies-bom` 中统一声明，子模块不得自行指定版本。
3. **安全优先**：安全能力通过自定义过滤器实现，非必要不引入 Spring Security。
4. **日志归一**：任何第三方库的日志（JCL、log4j、JUL）必须通过桥接器转接至 Logback。
5. **兼容性**：涉及数据库、缓存、对象存储的依赖，优先选择遵循标准协议（SQL 标准、Redis 协议、S3 协议）的实现，保证可替换性。

## 数据库选型说明

项目数据库为 **MySQL 8.x**，建表语句、字段类型、索引等均按 MySQL 8 编写，详见[数据库设计规范](数据库设计规范.md)。`requirements.txt`、`application.yml` 中的凭据一律通过环境变量注入，不得写入版本库。

## 对象存储选型说明

对象存储采用 **Silo**，而非直接使用 MinIO，原因与边界如下：

1. **MinIO 官方社区镜像已迁出 Docker Hub**，`minio/minio` 在公共镜像源均无法拉取，直接引用会导致一键部署失败。
2. **Silo 是 Pigsty 社区维护的 MinIO fork**，接续上游发行线并提供持续的安全修复，专为应对官方镜像撤出而维护。
3. **兼容性已在容器中实测**：`/minio/health/live` 健康端点、9001 控制台、`mc ready local`、`MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` 环境变量、`server /data --console-address` 启动命令均与 MinIO 一致；后端使用 MinIO Java SDK 8.5.7，**代码无需任何改动**。
4. **可替换**：`deploy/.env` 的 `MINIO_IMAGE` 可指定其他 S3 兼容实现（如自建镜像），后端仅依赖 S3 协议与预签名能力。

> 注意：环境变量名仍为 `MINIO_*`，这是 Silo 刻意保留的兼容约定，不代表运行时依赖 MinIO 官方镜像。
