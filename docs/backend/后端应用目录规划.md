# 后端应用目录结构

## 命名约定

- 项目统一英文前缀为 `drs`，Java 根包为 `cn.edu.fzu.drs`，对应目录 `cn/edu/fzu/drs`。
- 业务模块包路径为 `cn.edu.fzu.drs.module.{模块}.{分层}`，模块名为小写英文（`common` / `security` / `system` / `screening`）。
- 启动类位于根包下：`cn.edu.fzu.drs.DrsApplication`。

---

## 一、工程整体结构

```text
backend/                              # Maven 聚合工程（packaging=pom）
├─ pom.xml
├─ drs-dependencies/
│  └─ drs-dependencies-bom/           # 依赖版本声明（packaging=pom）
├─ drs-module/                        # 业务模块聚合目录（仅组织用，无 pom.xml）
│  ├─ drs-module-common/              # 统一响应、异常、常量、审计契约、密码工具
│  ├─ drs-module-security/            # 认证过滤器、权限拦截器、Token 服务
│  ├─ drs-module-system/              # 认证、用户、字典、操作日志
│  └─ drs-module-screening/           # 筛查上传、记录、统计、导出、模型信息
└─ drs-app/
   └─ drs-app-server/                 # 启动模块（fat-jar）
      ├─ pom.xml
      └─ src/main/
         ├─ java/cn/edu/fzu/drs/
         │  ├─ DrsApplication.java    # 启动类
         │  ├─ config/                # 全局异常、响应包装、MyBatis-Plus、审计配置
         │  └─ controller/            # 健康检查等应用级接口
         └─ resources/
            └─ application.yml        # 凭据以 ${DB_PASSWORD} 等占位符注入
```

**聚合目录说明**：`drs-dependencies/`、`drs-module/`、`drs-app/` 仅用于组织代码结构，本身不是 Maven 模块，不包含 `pom.xml`；其下每个具体模块/应用才是 Maven 模块，必须包含 `pom.xml`。

---

## 二、业务模块内部分层目录

以 `drs-module-screening` 为例：

```text
drs-module-screening/
├─ pom.xml
└─ src/main/java/cn/edu/fzu/drs/module/screening/
   ├─ client/            # 外部服务客户端（ModelInferenceClient）
   ├─ config/            # 模块级配置（MinioProperties、ObjectStorageConfig）
   ├─ controller/        # REST 接口层
   ├─ convert/           # Entity → VO 转换（手写静态工具类，不引入 MapStruct）
   ├─ dto/               # 请求对象（含分页查询）
   ├─ entity/            # 数据库实体
   ├─ mapper/            # MyBatis-Plus Mapper 接口（无 XML 映射文件）
   ├─ service/           # 业务接口
   │  └─ impl/           # 业务实现
   └─ vo/                # 响应对象
```

`drs-module-system` 结构相同（少 `client/`，另含字典、用户、日志相关类）；`drs-module-security` 按 `annotation / config / context / core / filter / interceptor / model / service / util` 组织；`drs-module-common` 按 `audit / constant / entity / exception / result / util` 组织。

### 分层职责

| 层 | 目录 | 职责 | 约束 |
| --- | --- | --- | --- |
| 接口层 | `controller/` | 接收请求、参数校验、封装统一响应、声明 Knife4j 注解 | 不写业务逻辑；不直接访问 Mapper |
| 业务逻辑层 | `service/` | 业务规则、事务控制、数据权限拼接 | 接口与实现分离，实现放 `impl/` |
| 数据访问层 | `mapper/` | 单表 CRUD 与条件查询 | 仅做数据存取，不含业务判断 |
| 实体层 | `entity/` | 与数据库表对应的持久化对象 | 禁止直接作为响应体返回 |
| 传输对象层 | `dto/`、`vo/` | 入参与出参 | DTO 加校验注解；VO 使用 Lombok |
| 转换层 | `convert/` | Entity → VO | 手写静态工具类，实体与 DTO 多为手写 getter/setter |

### 依赖方向

```
controller → service → mapper → entity
     ↓          ↓
    dto/vo    convert
```

- 严格单向依赖，禁止反向依赖或跨层调用。
- 跨模块调用通过对方的 `service` 接口，不得直接访问对方 `mapper` 或表。
- 依赖方向：`drs-app-server` → 各业务模块 → `drs-module-common`；`drs-module-security` 被业务模块依赖。

## 三、命名规则

| 类型 | 命名规则 | 示例 |
| --- | --- | --- |
| 模块目录 | `drs-module-{模块}` | `drs-module-screening` |
| 包路径 | `cn.edu.fzu.drs.module.{模块}.{分层}` | `cn.edu.fzu.drs.module.screening.controller` |
| 控制器 | `{资源}Controller` | `ScreeningRecordController` |
| 服务接口 / 实现 | `{资源}Service` / `{资源}ServiceImpl` | `ScreeningRecordServiceImpl` |
| 数据访问 | `{资源}Mapper` | `BizScreeningRecordMapper` |
| 实体 | `{表前缀}{资源}Entity` | `BizScreeningRecordEntity` |
| 请求对象 | `{资源}{操作}DTO` | `ScreeningPageQuery` |
| 响应对象 | `{资源}VO` | `ScreeningRecordVO` |
| 转换器 | `{表前缀}{资源}Convert` | `BizScreeningRecordConvert` |

- 类名使用帕斯卡命名法，包名全小写。
- 资源名与 REST 路径中的资源名词保持一致（`/screening-records` ↔ `ScreeningRecord`）。

## 四、文件放置约定

1. **实体与表一一对应**：使用 MyBatis-Plus 的 `@TableName`、`@TableId`、`@TableField`；实体需显式设置 `id`、`deleteFlag`、`createTime`、`updateTime`（项目未启用自动填充）。
2. **禁止 Entity 外泄**：Controller 返回值必须是 `VO`，入参必须是 `DTO`。
3. **单表查询用 Lambda**：优先使用 `LambdaQueryWrapper`，复杂统计在服务层组装；本项目不使用 XML 映射文件。
4. **清空字段需显式 set**：`updateById` 受字段策略 `NOT_NULL` 限制，无法把字段更新为 `null`，需用 `LambdaUpdateWrapper` 显式 `.set(...)`。
5. **配置集中**：应用级配置放 `drs-app-server/src/main/resources/application.yml`，模块级配置类放各模块 `config/`。
6. **自动装配声明**：`drs-module-security` 通过 `DrsSecurityAutoConfiguration` 自动装配过滤器与拦截器。
7. **构建产物不入库**：`target/` 由 `.gitignore` 忽略；执行 `mvn clean` 前需先停止占用 8080 的后端进程。
