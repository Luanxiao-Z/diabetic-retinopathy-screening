# 后端应用目录结构

## 命名占位符约定

下文中的 `{app}` 为**项目前缀占位符**，实际使用时替换为项目统一英文前缀（如 `drs`），全项目保持一致。
`{根包}` 为 Java 根包名（如 `com.example.drs`），`{根包路径}` 为对应目录路径（`com/example/drs`）。
`{模块}` 为业务模块名（小写英文，如 `system`、`screening`）。

---

## 一、工程整体结构

```text
backend/                              # 后端代码根目录
├─ pom.xml                            # 聚合 POM（packaging=pom）
├─ {app}-dependencies/                # 依赖声明聚合目录（仅组织用，无 pom.xml）
│  └─ {app}-dependencies-bom/         # 依赖版本声明模块（packaging=pom）
├─ {app}-app/                         # 应用构建聚合目录（仅组织用，无 pom.xml）
│  └─ {app}-app-{应用名}/             # 单个可启动应用
│     ├─ pom.xml
│     ├─ src/
│     │  ├─ main/
│     │  │  ├─ java/{根包路径}/
│     │  │  │  ├─ {应用名}Application.java   # 启动类
│     │  │  │  └─ config/                    # 应用级配置（跨域、拦截器、Filter 注册）
│     │  │  └─ resources/
│     │  │     ├─ application.yml
│     │  │     ├─ application-{env}.yml
│     │  │     └─ logback-spring.xml
│     │  └─ test/
│     │     ├─ java/{根包路径}/
│     │     └─ resources/
│     ├─ target/                      # 编译输出（不入库）
│     └─ build/                       # 应用工作目录
│        ├─ apps/                     # 本项目自有模块 jar
│        ├─ libs/                     # 第三方依赖 jar
│        ├─ etc/                      # 配置文件目录
│        └─ bin/                      # 启动停止脚本目录
└─ {app}-module/                      # 业务模块聚合目录（仅组织用，无 pom.xml）
   ├─ {app}-module-system/            # 业务模块：系统管理
   ├─ {app}-module-screening/         # 业务模块：筛查业务
   └─ {app}-module-{模块}/
```

**聚合目录说明**：`{app}-dependencies/`、`{app}-app/`、`{app}-module/` 仅用于组织代码结构，本身不是 Maven 模块，**不包含 `pom.xml`**；其下每个具体模块/应用才是 Maven 模块，**必须包含 `pom.xml`**。

## 二、业务模块内部分层目录（推荐结构）

每个业务模块为一个 Maven 模块，内部采用**按职责分层**的目录结构：

```text
{app}-module-{模块}/
├─ pom.xml
└─ src/
   ├─ main/
   │  ├─ java/{根包路径}/{模块}/
   │  │  ├─ controller/               # 接口层（REST 接口）
   │  │  │  └─ XxxController.java
   │  │  ├─ service/                  # 业务逻辑层
   │  │  │  ├─ XxxService.java        # 业务接口
   │  │  │  └─ impl/
   │  │  │     └─ XxxServiceImpl.java # 业务实现
   │  │  ├─ mapper/                   # 数据访问层
   │  │  │  └─ XxxMapper.java
   │  │  ├─ entity/                   # 数据库实体（与表一一对应）
   │  │  │  └─ XxxEntity.java
   │  │  ├─ dto/                      # 请求对象（入参）
   │  │  │  ├─ XxxQueryDTO.java       # 查询条件
   │  │  │  ├─ XxxCreateDTO.java      # 新增入参
   │  │  │  └─ XxxUpdateDTO.java      # 更新入参
   │  │  ├─ vo/                       # 响应对象（出参）
   │  │  │  └─ XxxVO.java
   │  │  ├─ convert/                  # 对象转换（MapStruct）
   │  │  │  └─ XxxConvert.java
   │  │  ├─ enums/                    # 业务枚举
   │  │  │  └─ XxxEnum.java
   │  │  ├─ config/                   # 模块级配置与自动装配
   │  │  │  └─ XxxAutoConfiguration.java
   │  │  ├─ exception/                # 模块级异常
   │  │  │  ├─ XxxException.java
   │  │  │  └─ XxxExceptionCode.java
   │  │  ├─ handler/                  # 模块级处理器（元数据填充、数据权限等）
   │  │  └─ util/                     # 模块内工具类
   │  └─ resources/
   │     ├─ mapper/                   # MyBatis XML 映射文件
   │     │  └─ XxxMapper.xml
   │     └─ META-INF/
   │        └─ spring/
   │           └─ org.springframework.boot.autoconfigure.AutoConfiguration.imports
   └─ test/
      ├─ java/{根包路径}/{模块}/
      │  ├─ service/                  # 业务层测试
      │  └─ controller/               # 接口层测试
      └─ resources/
```

### 分层职责

| 层 | 目录 | 职责 | 约束 |
| --- | --- | --- | --- |
| 接口层 | `controller/` | 接收 HTTP 请求、参数校验、封装统一响应、声明 Swagger 注解 | 不写业务逻辑；不直接访问 Mapper |
| 业务逻辑层 | `service/` | 业务规则、事务控制、编排数据访问 | 接口与实现分离，实现放 `impl/`；事务标注在此层 |
| 数据访问层 | `mapper/` | 单表 CRUD 与复杂查询 SQL | 仅做数据存取，不含业务判断 |
| 实体层 | `entity/` | 与数据库表一一对应的持久化对象 | 禁止直接作为响应体返回 |
| 传输对象层 | `dto/`、`vo/` | 入参（DTO）与出参（VO） | 入参必须做校验注解 |
| 转换层 | `convert/` | Entity、DTO、VO 之间的转换 | 使用 MapStruct，禁止手写大量 setter |
| 配置层 | `config/` | 模块级 Bean、配置属性、自动装配 | 需跨模块生效时配置自动装配文件 |
| 异常层 | `exception/` | 模块业务异常与异常码 | 异常码需登记到全局异常处理器 |

### 依赖方向

```
controller → service → mapper → entity
     ↓          ↓
    dto/vo    convert
```

- 严格单向依赖，**禁止反向依赖或跨层调用**。
- `controller` 不得注入 `mapper`；`service` 不得注入 `controller`。
- 跨模块调用必须通过对方的 `service` 接口，不得直接访问对方 `mapper` 或表。

## 三、命名规则

| 类型 | 命名规则 | 示例 |
| --- | --- | --- |
| 模块目录 | `{app}-module-{模块}`，模块名小写英文 | `{app}-module-screening` |
| 包路径 | `{根包}.{模块}.{分层}` | `com.example.drs.screening.controller` |
| 控制器 | `{资源}Controller` | `ScreeningRecordController` |
| 服务接口 | `{资源}Service` | `ScreeningRecordService` |
| 服务实现 | `{资源}ServiceImpl` | `ScreeningRecordServiceImpl` |
| 数据访问 | `{资源}Mapper` | `ScreeningRecordMapper` |
| 实体 | `{资源}Entity` | `ScreeningRecordEntity` |
| 请求对象 | `{资源}{操作}DTO` | `ScreeningRecordQueryDTO` |
| 响应对象 | `{资源}VO` | `ScreeningRecordVO` |
| 转换器 | `{资源}Convert` | `ScreeningRecordConvert` |
| 枚举 | `{含义}Enum` | `ScreeningStateEnum` |
| 异常 | `{模块}Exception` | `ScreeningException` |
| Mapper XML | 与 Mapper 接口同名 | `ScreeningRecordMapper.xml` |

- 类名统一使用**帕斯卡命名法**，包名统一**全小写**。
- 资源名与 REST 路径中的资源名词保持一致（如路径 `/screening-records` ↔ `ScreeningRecord`）。

## 四、文件放置约定

1. **实体与表一一对应**：一张表一个 `Entity`，字段与表字段一致，使用 MyBatis-Plus 注解 `@TableName`、`@TableId`、`@TableField`。
2. **禁止 Entity 外泄**：Controller 返回值必须是 `VO`，入参必须是 `DTO`，不得直接暴露 `Entity`。
3. **Mapper XML 集中放置**：XML 文件统一放 `src/main/resources/mapper/`，并在配置中指定 `mybatis-plus.mapper-locations=classpath*:/mapper/**/*.xml`。
4. **简单查询用 Lambda**：单表简单查询优先使用 MyBatis-Plus `LambdaQueryWrapper`，不写 XML；多表关联、复杂统计才写 XML。
5. **配置不打包进 jar**：应用配置放 `build/etc/`，模块默认配置放 `resources/`，两者通过 Spring Profile 覆盖。
6. **自动装配声明**：模块需被其他应用自动引入时，在 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 中声明配置类。
7. **测试与源码同构**：测试目录结构与源码保持一致，测试类名 `{类名}Test`。
8. **禁止提交构建产物**：`target/`、`build/apps/`、`build/libs/` 不入库。

## 五、跨应用复用时的模块拆分（可选）

当某模块需要被多个应用以"接口 + 远程实现"方式复用时，可拆分为多个 Maven 子模块，此时**每个子模块内部仍遵循第二节的分层约定**：

```text
{app}-module-{模块}/
├─ pom.xml                       # 聚合 POM（packaging=pom）
├─ {app}-{模块}-api/             # 对外接口与 DTO（不含实现）
│  └─ src/main/java/{根包路径}/{模块}/api/
│     ├─ service/{资源}Service.java
│     └─ dto/
├─ {app}-{模块}-service/         # 实现（controller/service/mapper/entity/...）
│  └─ src/main/java/{根包路径}/{模块}/
│     ├─ controller/ service/ mapper/ entity/ vo/ convert/ ...
└─ {app}-{模块}-common/          # 常量、枚举、异常、工具（被 api 与 service 共用）
   └─ src/main/java/{根包路径}/{模块}/common/
```

**拆分原则**：默认采用第二节的单模块结构；仅在确有跨应用复用需求时才拆分，避免过度设计。
